# 수현 작업 목록 · 사전 검사·수동 드릴 확인

2026-09-21 사용자 결정. 기준 main `829db40`, 작업 브랜치 `codex/hmi-preparation-flow`.
이 문서는 구현할 작업 목록이다. 이번 문서 수정으로 코드·공통 타입·실기 검증이 완료된 것은 아니다.
세은님 전달용 원본은 [공정 연결 인수인계](PROCESS_HANDOFF_20260921.md)다.

추가 권장안: [준비 Action 공통 구현 기준](PREPARE_WORKPIECE_ACTION.md). 실제 `.action`과 빌드 등록을 추가했다. 수현은 MEASURE 요청 → Result 저장 → 실측 profile 생성 → BIND_SNAPSHOT 요청/ack → 경로 생성 순서로 구현한다. 서버 연결은 아직 미구현이다.

## 이번에 고정한 동작

1. HMI의 **사전 검사 요청**으로 제어 노드가 로봇 상태 검사를 시작한다.
2. 연결·운전 가능 상태·제어권·정지·도구 설정 및 하드웨어 토픽 관측을 확인한다.
3. 홈이 아니면 이동 조건과 홈 경로를 검사하고 로봇팔을 홈으로 이동한다. 홈 도착·정지 후 상태 검사를 다시 수행한다. 홈 밖이라는 이유만으로 실패시키지 않는다.
4. 시율의 측정 함수가 그리퍼/도구의 지정 접촉부를 이용해 양초 윗면·사방을 접촉 측정하고 정상 후퇴한다. 현재 측정 구현의 옆면 8점을 연결 대상으로 한다.
5. 유효한 실측 스냅샷으로 경로 생성 → 미리보기 확인 → 사용자가 드릴을 수동으로 켜고 ON 체크 → 조각 요청 → 최종 관절 검사 → 조각 순서로 진행한다.

드릴 전원과 그리퍼 개폐는 프로그램의 제어 대상에서 제외한다. 측정·홈 이동·조각을 위한 로봇팔 제어와 실제 정지 확인은 유지한다.
드릴 ON 체크는 사람의 확인 UI다. 드릴 전원 센서값이나 제어 노드의 검사 결과로 표시하지 않는다.
측정 전 드릴 OFF와 작업 종료 후 전원 끄기는 운영자의 수동 절차로 안내한다. 프로그램의 자동 OFF를 약속하지 않는다.

모든 체크 항목은 이 결정에 대한 미완료 작업이다. 기존 MOCK 구현 여부와 구분한다.

`operator_confirmed_fixture`는 공작물 고정 확인이다. 드릴 ON이나 그리퍼 닫힘 필드로 재해석하지 않는다.
ON이 화면에만 있다는 것은 직접 HTTP 요청에 대해 ON 확인을 강제하지 않는다는 뜻이다. 이 제한을 수동 운영 절차로 명시한다.

## 현재 코드와의 차이

- main `829db40`: ON 전용 필드·체크박스 없음. 공통 타입은 `schema_version=2`이며 브랜치 이름의 v3/v4와 별개다.
- 로컬 미커밋 HMI: 준비 확인 3개를 받아 검증하는 MOCK HTTP 흐름이 있다. 위 결정에 맞게 수정해야 하며 ROS 준비 요청은 여전히 미연결이다.
- 세은 작업 브랜치의 준비 Action 초안: 운영자 확인 3개 후보를 그대로 확정하지 않는다. 관측은 제어가 수집하고 HMI는 요청·표시를 맡는다.
- 시율 PR #45: 홈 경유 구현 후보가 있다. 공정 내부 호출로 연결하고 HMI가 별도의 홈 명령을 보내지 않는다.
- `output/`의 기존 로드맵·ZIP·PDF는 이전 산출물이다. 이번 결정의 전달본은 이 문서와 인수인계 문서이며 기존 묶음을 최신판으로 배포하지 않는다.

## 세은·시율에게 받아야 할 정보

1. 실제 하드웨어 Topic 이름·메시지 타입·발행 주체·QoS·주기와 각 필드의 의미. 장착 판별 가능 범위와 미지원 항목 포함.
2. 기존 ProcessState로 보낼 수 있는 상태·출처·품질·시각 매핑. 하중 등 현재 메시지에 전용 필드가 없는 값은 공정 내부 검사와 상세 기록의 전달 범위를 구별.
3. [준비 Action 권장안](PREPARE_WORKPIECE_ACTION.md)에 맞춰 ID 발급·설정 조회·typed Result·BIND_SNAPSHOT을 구현하고 송수신 시험 결과를 대조. ON 필드는 포함하지 않음.
4. 홈 이동 전 조건 검사와 홈 도착 후 재검사 결과, 이미 홈인 경우의 진행·결과. 보호정지 등 다른 실패를 단순 비홈 상태와 구분.

실제 Topic이 확인되지 않은 항목을 새 이름이나 가짜 정상값으로 채우지 않는다. 그리퍼 닫힘만 제공되면 철사 고정이나 드릴 장착까지 자동 확인됐다고 표시하지 않는다.

## 구현 후 확인할 사례

- 수동 ON 체크로 장치 명령이 발생하지 않고 HTTP·ROS 요청 필드가 변하지 않는지 확인한다.
- 경로 변경·새 작업·취소·정지·종료·재접속에서 ON이 해제되는지 확인한다.
- 하드웨어 관측이 VALID/STALE/UNKNOWN/UNSUPPORTED일 때 출처·시각과 표시가 일치하는지 확인한다.
- 이미 홈이면 이동 생략, 비홈이면 검사된 홈 이동과 재검사, 재검사 실패면 측정 미호출을 검증한다.
- 홈 이동 중 취소·시간 초과·정지 미확인, 측정 실패 뒤 후속 명령 차단을 검증한다.
- 정상 준비부터 동일 스냅샷·경로의 미리보기·최종 검사·실행까지 ROS SIM과 실기를 구분해 기록한다.
