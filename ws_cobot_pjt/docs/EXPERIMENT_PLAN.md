# 음각·세척·통합 시험과 기록 계획

2026-09-17 설계안. 아래는 앞으로 수행할 시험이며 아직 측정한 실기 결과가 아니다. 합격 수치와 반복 횟수는 예비 시험 및 팀 합의로 정한다. [기존 오프라인 결과](ALGORITHM_VALIDATION.md)와 구분해 기록한다.

## 비교 조건

한 번의 비교에서는 재료 상태, 도안 크기, 공구·TCP, 지그, 명령 깊이·속도, 진행 방향을 고정하고 변경한 조건을 명시한다. 지점토와 비누베이스의 결과는 별도로 집계한다. 원기둥 각도별 시험에서는 각도의 기준 방향도 기록한다.

## 시험 순서와 연구 대상

| 단계 | 확인할 연구 대상 | 기록·판정 |
|---|---|---|
| 1. 도안 전환 | 새 도안의 입력·전처리·미리보기 확인에 드는 시간 | 도안 ID별 준비 시간, 사람 작업 시간, 처리 오류 |
| 2. 평면 단순선 | 명령 깊이·속도·공구 방향과 실제 홈의 관계 | 실측 홈 깊이·폭·끊김·뭉침, 공구·재료 상태 |
| 3. 원기둥 단순선 | 둘레 각도에 따른 자세·도달·가공 품질 | 각도별 홈 깊이·폭·실패율. 실제 좌표 기준과 접근 범위 |
| 4. 공구 파지·반납 | 반복해서 잡았을 때 헤라 끝 위치 유지 | 파지 성공, 재파지 위치 변화, 반납·해제 확인 |
| 5. 중간 세척 | 스펀지의 제거 효과와 공구·패드 상태 | 잔여물, 찢김·조각 전이, 파지 이동, 왕복 포함 세척 시간 |
| 6. 세척 주기 | 누적 가공 거리와 홈 품질 저하의 관계 | 세척 없음과 주기적 세척 비교. 재료별 주기와 패드 교체 기준 |
| 7. 전체 통합 | 도안 입력부터 가공·세척·반납·기록까지 | 단계 누락, 중복 실행, 정상 완료와 제품 합격 분리 |
| 8. 오류 흐름 | 후속 실행 차단과 상태 기록·복원 | 모의 응답으로 오류·지연·연결 단절을 먼저 확인. 실제 장비에서 위험한 장애를 일부러 만들지 않음 |

## 시간 정의

- 도안 전환 준비 시간: 새 도안 입력 시작부터 현장 실행 조건을 포함한 작업 준비 완료까지의 경과 시간. 재료·공구 교체가 포함되었는지 함께 기록한다.
- 알고리즘 처리 시간: 처리 시작부터 결과 생성까지의 PC 계산 시간.
- 사람 작업 시간: 파일 편집·확인·재료 배치 등 작업자가 실제 개입한 구간의 합. 자동 계산·대기 시간과 구분한다.
- 가공 접촉 시간: 공구가 재료를 가공하는 구간의 시간.
- 세척 시간: 재료 이탈부터 스펀지 왕복·닦기 후 다음 선의 접근 준비까지. 닦는 접촉 시간만 별도로 기록할 수 있다.
- 전체 사이클 시간: 실행 시작부터 공구 반납·복귀 완료까지. 품질 검사 시간을 포함하는지 별도 표기한다.

## 한 시험 행에 남길 항목

| 구분 | 필드 |
|---|---|
| 식별 | 시험 ID, 작업 ID, 도안 파일·해시, 날짜, 작업자, 시험한 커밋 |
| 조건 | 재료·상태, 원기둥 지름·높이, 기준 각도, 공구·TCP·지그 설정 버전 |
| 명령 | 설정 깊이, 속도, 공구 각도, 진행 방향, 세척 주기 |
| 시간 | 전환 준비, 계산, 사람 작업, 가공, 세척, 전체 사이클 시간 |
| 품질 | 측정 위치, 실제 홈 깊이·폭, 끊김·뭉침·누락 여부, 합격 여부 |
| 세척 | 세척 구간 번호, 누적 가공 길이, 횟수, 잔여물, 패드 손상, 파지 변화 |
| 실패 | 발생 단계, 오류 내용, 마지막 완료 선, 조치, 재개 여부 |

깊이는 명령한 침투량과 실측 홈 깊이를 따로 기록한다. 로봇 TCP의 Z좌표를 실제 홈 깊이라고 기록하지 않는다. 원기둥에서는 표면 법선 방향과 실제 표면 기준을 함께 고려한다.

각도별 실패율은 `해당 각도의 실패 시험 수 / 해당 각도의 전체 시도 수 × 100`으로 계산하고 시도 수를 함께 표시한다. 실패 정의와 제외·중단 처리 규칙을 먼저 정한다. 반복 수가 적은 예비 결과를 서비스 전체 성공률로 일반화하지 않는다.

## 시스템 통합 확인

- 도안 생성과 실기 시작 요청을 구분하고, 준비 조건이 없으면 실행하지 않는다.
- 같은 작업의 시작 버튼을 여러 번 눌러도 중복 실행하지 않는다.
- 가공·세척·오류·반납 단계 표시와 실제 완료 기록을 대조한다.
- 로봇 상태 수신이 끊긴 모의 조건에서 오래된 정상 값을 계속 표시하지 않는다.
- 선 중간 중단은 미완료로 기록하며 원인·좌표 기준·재개 경로를 확인한 뒤 재개한다.
- 웹 화면 종료, DRL 종료, 로봇 정지, 제품 합격을 서로 다른 사건으로 관리한다.
