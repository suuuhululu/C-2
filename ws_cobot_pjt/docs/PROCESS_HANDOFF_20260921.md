# 세은님 전달 · 사전 검사·홈 복귀·수동 드릴 운영 결정

2026-09-21 사용자 결정. 확인 기준 main `829db40`, HMI 작업 브랜치 `codex/hmi-preparation-flow`.
이 문서는 전달용 변경 요구사항이다. 공통 타입 구현·팀원 승인·실기 검증 완료를 의미하지 않는다.
수현 작업은 [HMI 작업 목록](HMI_ACTION_ITEMS_20260921.md)에 정리했다.

추가 권장안: [준비 Action 공통 구현 기준](PREPARE_WORKPIECE_ACTION.md), `c2_interfaces/action/PrepareWorkpiece.action`을 작성·빌드 등록했다. 세은은 `/c2/prepare_workpiece`의 MEASURE 서버와 이동 없는 BIND_SNAPSHOT 검증/등록을 구현한다. 수현은 결과 저장 뒤 BIND ack를 받아 경로 생성한다. 아래 과거 초안의 미정 표현보다 이 권장안을 우선 검토하되, 연결 완료로 보지 않는다.

## 전달할 핵심 내용

세은님, 사전 검사와 드릴 운영 범위를 아래와 같이 고정합니다.

1. 드릴 ON은 사용자가 물리 버튼을 눌러 켜고 HMI 체크박스를 수동으로 체크합니다. HMI 화면의 실행 확인에만 쓰며, 백엔드나 ExecuteProcess에 ON 필드를 보내지 않습니다. 공정 코드에서 ON bool 검사·자동 전원 판정·확인 응답 대기 단계를 구현할 필요가 없습니다.
2. 프로그램에서 그리퍼 열기/닫기와 드릴 ON/OFF 명령을 내리지 않습니다. 장착 관련 상태는 실제 하드웨어 Topic을 읽어 확인 가능한 범위에서 판단·표시합니다. HMI의 작업자 확인 bool을 장착 센서값으로 사용하지 않습니다.
3. HMI에서 사전 검사 요청을 받으면 로봇 상태·정지·도구 설정을 검사합니다. 홈이 아니면 조건과 경로를 검사한 뒤 홈으로 이동하고, 홈 도착·정지 확인 후 상태 검사를 다시 수행합니다. 비홈이라는 이유만으로 준비 실패를 반환하지 않습니다.
4. 재검사를 통과하면 시율님의 양초 측정 함수를 호출해 윗면·사방 접촉 측정과 정상 후퇴까지 수행합니다. 측정 전 OFF는 운영자가 수동으로 수행하는 절차입니다.

## 공정 호출 순서와 책임

| 순서 | 제어 노드 / 내부 함수의 책임 | HMI 표시 |
| --- | --- | --- |
| 요청 접수 | 동일 요청 중복 방지, 측정·조각 단일 소유권, 설정 참조 확인 | 사전 검사 접수 |
| 이동 전 검사 | 실제 로봇 연결·운전 가능 상태·제어권·현재 관절/TCP·정지·보호정지·TCP/하중/도구 오프셋 확인, 하드웨어 Topic 관측 검사 | 로봇 상태 검사 |
| 홈 확인 | 확인한 현재 자세와 설정의 홈 조건 대조 | 홈 확인 |
| 필요 시 홈 이동 | 시율 함수가 이동 전 경로/IK/간섭 조건을 검사하고 홈 이동. 이미 홈이면 이동 생략 | 홈 이동 중 / 이동 생략 |
| 홈 도착 재검사 | 실제 도착·정지 확인 후 최신 로봇 상태·제어권·정지/오류·도구 설정·장착 관측을 다시 검사 | 홈 도착·재검사 |
| 양초 측정 | 측정 접근/터치/후퇴 검사 후 윗면·사방 접촉. 현재 구현은 옆면 8점. 정상 후퇴·최종 기하 유효성 확인 | 윗면·옆면 진행 및 결과 |
| 결과 반환 | 원본·부분 결과·실패·정지 확인을 보존하고 HMI에 반환. 사용 가능한 기하만 후속 생성 허용 | 사전 검사 완료 또는 실패/미확인 |
| 경로 생성 이후 | 별도 ExecuteProcess 요청에서 준비/설정/경로 동일성·최종 관절 검사 후 검사한 경로 실행 | 미리보기 → 수동 ON 체크 → 조각 요청·진행 |

“홈으로 돌아와 재검사”는 정상 준비 절차다. 보호정지·통신 상실·제어권 없음·안전한 홈 경로 없음·취소·이동 실패까지 무시하고 이동하라는 의미가 아니다.
이 경우 원래 실패/미확인 상태를 반환하고 다음 측정으로 진행하지 않는다. 홈 재검사 실패 뒤 무제한 홈 이동·재시도도 하지 않는다.
실패 후 자동 복귀와 정상 준비 중 홈 진입은 구별한다. 정지·취소 이후 새 복귀 명령을 보내지 않는다.

홈 이동의 모션 구현은 시율 측정 모듈에 한 번만 둔다. 세은 상태 기계는 그 함수를 호출하고 결과를 판단하며 별도 홈 이동을 중복 실행하지 않는다.
PR #45의 홈 도착 확인만으로 도구·제어권을 포함한 전체 재검사까지 구현됐다고 보지 않는다. 최신 관측으로 재검사하는 연결 위치를 두 담당자가 확인해야 한다.

## 하드웨어 관측 전달

공급자 드라이버의 실제 Topic → 제어 노드/어댑터 관측 → 기존 `/c2/process_state` → HMI 흐름을 사용한다.
팀 노드 3개와 기존 역할을 유지하며 별도 그리퍼 노드를 추가하지 않는다.

기존 ProcessState에서 사용할 수 있는 필드는 다음과 같다.

- 도구: `requested_tool_id`, `mounted_tool_id`, `tool_confirmation_source`.
- 그리퍼: `grip_state`, `grip_quality`, `grip_measured_at`.
- 로봇: `robot_connection_state`, `robot_mode`, `robot_quality`, `robot_measured_at`.
- 관절/TCP: `joints`와 품질/시각, `tcp`와 `tcp_quality`, `tcp_profile_id`.

이 필드들은 전달 그릇이다. 실제 장치가 장착 식별·철사 고정·드릴 회전 상태를 모두 제공한다는 뜻은 아니다.
닫힘 신호만으로 `mounted_tool_id=engraving_drill` 또는 장착 성공을 생성하지 않는다. 미지원/오래된 관측을 정상으로 바꾸지 않는다.
하중의 실제 확인은 제어 내부에서 수행하며 현재 ProcessState에 없는 전용 하중 필드를 임의로 추가하지 않는다.

연결 전에 실제 Topic 이름·타입·발행 주체·필드 의미·QoS·주기·신선도 기준을 시율님과 대조해 알려주세요.
필수 장착 확인을 뒷받침할 신호가 없다면 미확인 항목과 현장 확인 과제를 남깁니다. 이 문서는 확인되지 않은 센서를 새로 존재하는 것으로 가정하지 않습니다.

## 수동 드릴 확인의 범위

수현이 ON 체크 UI와 경로 변경·새 작업·취소/정지·종료·재접속 시 해제를 구현한다.
ON 체크는 장치 전원을 바꾸지 않고 ROS 메시지나 공정 인터록도 아니다. 직접 HTTP 요청은 ON UI를 거치지 않으므로 시스템이 드릴 전원을 보장한다고 설명하지 않는다.
측정 중 OFF 유지, 조각 전 수동 ON, 취소·오류·종료 후 수동 OFF를 운영 안내에 표시한다. 로봇 정지와 드릴 전원 OFF를 같은 완료로 보고하지 않는다.

## 반영 상태·전환·검증

- main `829db40`: 공통 타입 v2, 준비 ROS Action 미반영. HMI ON 전용 체크도 없음.
- 로컬 HMI: 준비 세 bool 필수인 MOCK 구현이 남아 있다. 이번 문서는 이 코드를 바꿀 요구사항이며 변경 완료 보고가 아니다.
- 시율 [PR #45](https://github.com/suuuhululu/C-2/pull/45): `cb3ef1b` 홈 진입, `aea59da` 후속 수정. 전체 8점 실기 성공과 횡오차 원인 검증은 남아 있다.
- 준비 계약의 이름·필드·버전·상세 결과/스냅샷 연결은 송수신자가 한 번에 확정해 같은 설치본으로 배포한다. 이번 결정 때문에 드릴 ON 통신을 추가하지 않는다. 기존 배포 v2 타입·schema_version을 이 문서만으로 변경하지 않는다.
- 로컬 MOCK HTTP 입력에서 세 bool을 제거할 때 화면·서버·모의 상대·시험을 함께 변경하고 재빌드/재시작한다. 과거 기록은 보존하되 이전 성공을 새 관측 검사 통과로 재사용하지 않는다.
- 정상 홈, 비홈 복귀 및 재검사, 홈 경로 거절, 재검사 실패, 이동 중 취소/시간초과/정지 미확인, 장착 관측 누락/오래됨, 전체 측정과 동일 경로 실행을 검증한다. 그리퍼/드릴 제어 호출이 없는지도 확인한다.

이 문서의 최초 수정은 요구사항 정리였다. 후속 준비 Action 타입/빌드 시험 범위는 [준비 Action 검증 기록](VALIDATION_PREPARE_ACTION_20260921.md)에서 구분한다. 서버/클라이언트 기능 통합·로봇 이동은 별도이며 REAL/test_only 제한은 기존대로 유지한다.
