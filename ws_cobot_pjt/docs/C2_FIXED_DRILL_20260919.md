# 9/19 고정 드릴 운영·구조·인터페이스 변경

2026-09-19. 기준 main `301ea6e`(공통 타입 PR #21 병합)에서 사용자에게 전달된 이시율 제안과 사용자의 반영 요청을 대조했다. 이 문서는 구현 목표·이번 수정·미확정 값을 구분한다. 제안서의 “PR을 대신한다”는 표현은 저장소 검토·보호 규칙을 변경하지 않으며 본 변경도 작업 브랜치와 PR로 제출한다.

## 운영 기준

- 도구는 `engraving_drill`, 제어기 TCP는 그리퍼 끝점 `GripperDA_v1`, 경로 프레임은 `c2_base`다.
- 드릴은 철사로 고정한다. 사람이 철사를 제거하고 새 운영 절차를 승인하기 전까지 **그리퍼 열기 금지**다. DO2, `open()`, 반 열기, 초기화·종료·오류·정지·복구·보정 중 열기까지 포함한다. 단순히 코드를 바꾸거나 재시작했다고 이 제한을 해제하지 않는다. DO2는 전달된 금지 대상 표기이며 실제 I/O 배선·극성 확인의 대체가 아니다.
- 자동 집기·반납·청소는 현재 공정에서 제외한다. 확인을 위해 그리퍼를 열었다 닫거나 무조건 닫는 동작도 추가하지 않는다.
- 닫힘 관측과 드릴 장착·철사 고정 확인은 서로 다른 조건이다. `preconditions.py`에서 확인 출처·시각·신선도·실패를 검사한다. “닫힘 한 줄”만으로 성공을 가정하지 않는다. 지원 센서가 없으면 명시적인 운영자 확인 절차가 필요하며 자동 GRIPPED 추정은 금지한다.
- 경로 waypoint는 도구 끝 기준 m/quaternion xyzw. 툴 −Y가 표면 안쪽 법선, 툴 +Z가 원통 축 아래를 향한다. 제어기 TCP로의 오프셋 변환은 robot_adapter 한 곳에서 수행한다.
- 한 획의 연속 둘레 각도 범위는 180° 이내이며 이음매를 넘지 않는다. 획 순서로 J6 누적 회전을 줄이는 왕복을 계획하되, 각도 제한만으로 J6 안전을 보장하지 않는다. 현재 관절·IK 해·전체 APPROACH/CUT/TRAVEL/RETRACT 경로와 보정 접근까지 검사하고 한계·여유값이 미확정이면 REAL을 거절한다. 자동 손목 풀기·홈 복귀를 추가하지 않는다.

## 보정과 불변 설정의 순서

`장착 → 승인된 준비 절차에서 3점 전체 보정 → 보정 근거를 포함한 새 설정 스냅샷 → GeneratePath → 미리보기 확인 → ExecuteProcess`

실행 중 단계는 `PRECHECK → TOOL_CHECK → APPROACH → ENGRAVE → RETRACT → FINISH`다. TOOL_CHECK는 **저장된 보정값에 대한 1점 확인**이며 현장 확정된 접근·힘·정지 프로파일이 먼저 필요하다. ±1 mm는 제안값이고 이번 변경에서 REAL 기본값으로 설정하지 않는다.

1점 확인이 어긋나거나 측정이 불확실하면 `PROFILE_MISMATCH` 또는 `NOT_READY`로 중단한다. 실행 중 보정값·프로파일·경로를 조용히 덮어쓰지 않는다. 전체 재보정이 필요하면 새 스냅샷·경로 생성·미리보기 확인으로 돌아간다. 장착 3점 측정은 작업대상을 매 실행마다 다시 찾는 기능이 아니다.

`tool_calibration.py`는 노드가 아닌 내부 모듈이다. 전체 보정 결과에는 성공/실패, 측정 시각·근거, 도구/장착 식별, TCP 프로파일, 드릴 끝 오프셋(m, 툴 좌표계), 잔차·검증 상태를 담도록 담당 PR에서 정의한다. 보정 산출물은 설정 스냅샷의 ID·해시에 묶는다. 별도 보정 Action/Service나 ROS 필드를 이번에 임의로 추가하지 않는다. 전체 보정 기동은 실행 공정과 모션 소유권을 공유하는 승인된 준비 절차로 설계하며 외부 UI/API는 별도 합의 대상이다.

현재 어댑터의 `move`, `probe_touch`, `set_tool_offset`는 동기 함수다. 공정 노드는 작업 스레드 등으로 호출을 격리해 ROS 정지·상태 처리를 계속할 수 있어야 한다. 문서의 비동기 실행 요구를 현재 함수가 이미 awaitable하다는 뜻으로 해석하지 않는다.

작업 중 원격을 다시 조회했으며 main은 `301ea6e` 그대로다. 아래 소스는 아직 미병합이다. 각 PR의 모의 시험 보고나 repository-checks 성공을 이 변경의 통합·실기 검증으로 취급하지 않는다. 담당 영역 코드를 이번 브랜치에 복사하거나 승인·병합하지 않았다.

PR #27의 3점 함수 반환은 `StepResult.observed_state['calibration']`이며 성공 시 어댑터 오프셋을 적용한다. `verify_tool_tip`은 확인 중 오프셋을 비웠다가 저장된 값으로 복구한다. 이 내부 처리가 설정 스냅샷의 변경 허용을 뜻하지는 않는다. 전체 보정은 경로 생성 전 준비 절차에서만 기동하고, 실행 시에는 이미 승인된 동일 보정만 확인한다. 아직 없는 외부 보정 요청 API를 임의로 추가하지 않는다.

같은 PR에서 확인 터치 후 이탈 `adapter.move(...)`의 반환을 검사하지 않고 오차만으로 성공을 반환하는 부분을 확인했다. 담당 PR에서 이탈 실패·취소·정지 미확인을 성공으로 덮어쓰지 않는 시험과 결과 전파가 필요하다. 3점 적합 잔차도 반환은 있으나 허용 잔차에 따른 거절 조건은 별도 확정해야 한다. 이 문서는 해당 실기 코드를 수정하거나 사용 승인을 부여하지 않는다.

좌표·공정 노드가 아직 구현되지 않아 실제 송수신 통합은 남아 있다. 위 차이를 맞춘 뒤 타입·경로 샘플·프로파일·소비자를 같은 버전으로 통합 검증하고 배포한다.
