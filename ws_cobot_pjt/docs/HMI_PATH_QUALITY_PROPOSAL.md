# 경로 진행·가공 판정 실시간 표시 계약 제안

2026-09-18. 사용자 요구: 예정 경로는 검정, 정상 가공 확인은 초록, 이동했으나 압력 등이 확인되지 않은 구간은 빨강으로 구분한다.

이 문서는 **좌표 담당·공정 담당과 합의할 제안**이다. 기존 `GeneratePath`, `ExecuteProcess`, `ProcessState`, `ProcessEvent`의 ROS 타입을 변경하지 않았다. 현재 HMI에는 `mock-execution-preview/1`이라는 로컬 모의 확장만 구현했다.

## 1. 판정 의미

| 화면 | 의미 | 증거 |
|---|---|---|
| 검정 | 예정, 아직 수행하지 않은 구간 | 해당 실행의 명시적인 NOT_STARTED |
| 황색 | 진행 중 | 현재 구간·점 범위의 이동 진행 |
| 초록 | 가공 조건 충족 확인 | 이동 완료와 필요한 접촉/힘 조건 충족이 모두 확인됨 |
| 빨강 | 가공 조건 실패 | 압력 부족 등 측정에 근거한 실패 판정·사유 |
| 회색 점선 | 판단 불가 | 센서 미지원·결측·통신 단절·정지 중 중단 등 |

‘압력이 확인되지 않았다’는 두 경우로 나눈다. 유효한 측정으로 요구 압력을 충족하지 않았음을 확인했다면 실패다. 측정 자체가 없으면 미확인이다. 단순히 명령을 보냈거나 이동이 끝났거나 진행률이 100%라는 이유로 초록으로 바꾸지 않는다. 초록 역시 최종 외관 검사 합격은 아니다.

## 2. 좌표 담당자에게 필요한 정보

- 전체 경로의 `path_id`, 버전, SHA-256 및 `stroke_id`, `segment_id`.
- 세그먼트 내 원본 waypoint 인덱스와 최종 U/V·3D 점의 대응 관계.
- 축소 미리보기 점마다 대응하는 원본 인덱스 또는 원본 구간 범위. 시작·끝·분할점 보존.
- 이음매에서 분리된 조각과 원래 획의 관계, 재연결 금지 경계.
- 가공(CUT) 구간과 접근·이탈·이동 구간의 분리. 비가공 구간에 가공 품질을 잘못 표시하지 않는다.

전체 세그먼트 단위 표시만으로는 중간 3mm 누락 등을 표현할 수 없다. 예를 들어 원본 segment의 점 40~52가 실패했다면, HMI는 그 점 범위에 대응하는 선만 빨강으로 표시해야 한다. 축소 결과의 ‘40번째 점’으로 오해하면 안 된다. 현재 모의 예제는 세그먼트 전체 범위를 사용하며 실제 축소 대응은 미구현이다.

## 3. 공정 담당자에게 필요한 정보

| 정보 | 이유 |
|---|---|
| run ID + path ID/버전/해시 | 이전 실행이나 다른 도안의 결과가 덮이지 않도록 연결 |
| segment ID + 원본 점 시작/끝 범위 | 표시할 실제 구간 식별 |
| 이동 상태 | NOT_STARTED / MOVING / COMPLETED / UNKNOWN 등 의미 합의 |
| 가공 판정 | PENDING / IN_PROGRESS / PASSED / FAILED / UNKNOWN 등 의미 합의 |
| 실패·미확인 사유 | 압력 미달, 센서 미지원, 결측, 정지 중단 등을 구분 |
| 판정 시각·sequence·source epoch | 지연·중복·역순·노드 재시작 구분 |
| 측정 quality와 측정 시각 | 오래된 값을 새 heartbeat로 오인하지 않음 |
| 적용한 판정 설정 스냅샷 | 기준 변경 후에도 당시 판단 근거 보존 |

접촉력을 쓸 경우 **어느 좌표계의 어떤 방향 성분을 가공 압력으로 볼지** 먼저 합의한다. 곡면 법선 방향 힘인지, 센서 제공 축인지, 부호·단위·도구 자세와의 관계가 필요하다. 단순한 베이스 Z 힘을 곡면 전체의 접촉력으로 가정하지 않는다.

허용 힘 범위, 유지 시간, 샘플 주기, 결측 허용 여부, 필터·히스테리시스, 구간 합격 비율, 실패 시 정지 정책은 현장 검증값을 사용한다. 이 문서에서 임의 수치로 확정하지 않는다. 판정은 센서와 제어 타이밍을 아는 공정 노드가 수행하고 HMI는 결과를 표시·저장한다.

## 4. 전달 방식 합의

진행 스냅샷과 구간별 최종 판정 이벤트를 분리하는 방식을 권장한다. 현재 ProcessEvent에는 segment_id가 있지만 부분 점 범위·힘 판정 필드는 합의돼 있지 않다. 공통 인터페이스 PR에서 기존 이벤트 확장 또는 별도 품질 이벤트 타입을 결정해야 한다. 여기서 새 ROS Topic 이름이나 `.msg`를 선점하지 않는다.

실시간 화면 갱신 주기와 센서 샘플 주기는 다르다. HMI가 모든 센서 샘플을 직접 받을 필요는 없지만, 일시적인 불량 구간이 중간 스냅샷 생략으로 사라지지 않게 최종 판정 이벤트·재조회 방법이 필요하다. 재접속 시 누적 구간 판정을 복구해야 한다.

## 5. 지금 구현된 모의 버전

- 공정 관제의 전개면과 원기둥에 같은 구간 색상을 표시한다.
- 가짜 이동 상태와 가짜 가공 판정을 별도로 기록한다. 압력 수치는 null이다.
- 정상 시나리오에서는 확인된 구간을 순서대로 초록으로 표시한다.
- ‘모의 압력 확인 실패’에서는 cut-006을 이동 완료·가공 실패로 표시하고 더 진행하지 않는다.
- 가공 중 정지된 구간은 회색 점선으로 남긴다. 자동 재가공하지 않는다.
- run의 `execution_preview` JSON을 새 SQLite 실행 기록에 보존한다. 실제 센서 원시 시계열 저장은 아직 구현하지 않았다.

이 모의 형식·중단 정책은 실제 힘 제어 계약이나 현장 안전 검증을 대신하지 않는다. 공통 계약이 확정되면 실제 이벤트를 같은 HMI 표시 모델에 변환하는 어댑터를 추가한다.
