# 시스템 모니터·좌표 생성·고정 드릴 공정 인터페이스 안내

**2026-09-20**, main `72618aa` 확인. [디렉토리·담당](SYSTEM_STRUCTURE.md), [공정 파일·함수·상태](../ws_cobot1/src/c2_process/README.md), [배포된 상세 계약 v2](INTERFACE_RECOMMENDATION.md)를 구분해 읽는다.

## 현재 코드와 이번 변경 범위

HMI·서버·공통 타입, c2_path 계산·GeneratePath Action 서버, c2_process 어댑터·도구 보정·관절 검사·조각 소스가 main에 있다. c2_path는 SIMULATION/test_only이며 공정 ROS 노드·패키지 설정은 main에 없다. 김세은의 부분 통합·실패·정지 시험 보고는 담당자 작업 현황으로 구별한다. 전체 실기 통합 완료로 표시하지 않는다.

이번 변경은 **역할·구현 상태와 새 호출 순서의 문서화**다. ROS 타입·서버·HMI 코드를 수정하지 않으며 schema_version은 2 그대로다. 아래 새 흐름을 v2 클라이언트가 이미 지원한다고 해석하지 않는다.

## 유지하는 통신 경계

| 통신 | 형식 | 담당 간 연결 |
| --- | --- | --- |
| `/c2/generate_path` | GeneratePath Action | 이수현 HMI/서버 ↔ 노홍동 좌표 노드 |
| `/c2/execute_process` | ExecuteProcess Action | 이수현 HMI/서버 ↔ 김세은 공정 노드 |
| `/c2/stop_process` | StopProcess Service | HMI/서버 → 공정, 정지 접수 응답 |
| `/c2/process_state` | ProcessState Topic | 공정 → HMI, 현재 상태 |
| `/c2/process_events` | ProcessEvent Topic | 공정 → HMI, 사건 기록 |

김세은의 공정 모듈과 이시율의 보정·모션 모듈은 **같은 공정 노드 안의 Python 함수 호출**로 연결한다. 이시율 모듈에서 어댑터를 호출하면 어댑터가 공급자 드라이버와 통신한다. 파일 담당자가 다르다는 이유로 중간 ROS Topic이나 별도 보정 노드를 만들지 않는다.

## 순서 변경안과 기존 v2의 차이

| 항목 | 기존 v2 계약 | 9/20 통합 목표 |
| --- | --- | --- |
| 경로 생성 전 | 장착 3점 도구 보정·불변 설정 준비 | 유지. 도구 장착 기준 확보 |
| 실행 요청 직후 | PRECHECK에서 경로/설정·준비·전체 경로 J6 확인 | 원본 유효성·기본 준비 확인. 실물 측정 이동은 별도 사전 검사 |
| 양초 위치 변화 | 저장 보정의 1점 확인 실패 시 중단·재준비 | 드릴 OFF로 양초 중심·축/기울기 등을 측정해 새 실행 경로 생성 |
| 최종 관절 검사 | 원래 요청 경로 기준 | 실측·깊이·연결 이동을 적용한 최종 경로 기준 |
| 경로 동일성 | 미리보기한 요청 경로=실행 경로 | 원본→보정된 최종 경로를 명시적으로 연결. 최종 표시=검사=실행 경로 |
| 드릴 전원 | 별도 취소 가능한 확인 입력 미정 | 측정 OFF, 조각 직전 운영자 ON 확인 대기·취소 지원 |

**목표 순서:** 이미지→SVG·기준 경로→미리보기→실행 요청→기본 준비→양초 측정→새 실행 경로→최종 검사→최종 미리보기/드릴 확인→조각·이탈→완료.

이는 김세은이 공유한 기존 PRECHECK 관절 검사 → TOOL_CHECK에서 달라지는 연결 변경안이다. 공통 상태 기계 반영은 담당자 간 계약 확인 후 진행한다. 측정 과정의 이동까지 최종 검사 뒤로 미루는 뜻은 아니다.

## 연결 전에 합의할 계약

1. **원본·실행 경로:** 원본 `path_id/path_version/path_sha256`를 보존하고 파생 실행 경로를 별도로 등록한다. `run_id`에 보정·도구·설정 스냅샷과 최종 경로·검사 결과를 연결한다. 서로 다른 내용을 같은 해시로 표시하지 않는다.
2. **HMI 전달:** 보정 전/후 경로 참조, 보정 시각·유효 조건·잔차, 최종 검사 결과·문제 구간·미검사 항목을 전달할 필드와 조회 방법을 정의한다. v2의 문자열 필드를 임의 JSON으로 우회하지 않는다.
3. **상태/입력:** 측정·최종 검사·운영자 확인 대기를 HMI에 어떻게 표시할지, 드릴 ON 확인과 취소를 어떤 입력으로 받을지 김세은·이수현이 맞춘다. 현재 v2의 PRECHECK/TOOL_CHECK/APPROACH/ENGRAVE/RETRACT/FINISH에 새 단계가 이미 추가된 것은 아니다.
4. **함수 반환:** 이시율은 측정·보정된 최종 경로·실행 결과와 취소/힘 초과/보호정지/시간 초과별 정지·후퇴 상태를 제공한다. 김세은은 `joint_check.py`의 관절 검사를 구현하고 그 결과로 실행 가능 여부를 판단하며, FAILED/STOPPED/UNKNOWN 이후 조각·홈으로 진행하지 않는다. 정확한 함수 인자와 준비 경로 반환 형식은 통합 전에 공유한다.
5. **버전 전환:** 합의 후 타입·필드·의미 변경의 호환성을 판단하고 문서·c2_interfaces·송수신자·시험을 함께 갱신한다. 이번 문서만으로 REAL 차단·test_only를 해제하지 않는다.

## 단위·관측·운영

- 도구 끝 경로는 `c2_base`, m·quaternion xyzw, 관절 rad. 제어기 TCP는 `GripperDA_v1`, 도구는 `engraving_drill`. 변환은 robot_adapter 한 곳에서 수행한다.
- 관측은 출처·단위·좌표계·측정 시각·유효성을 포함한다. 통신 heartbeat가 살아 있어도 오래된 측정값을 유효하게 바꾸지 않는다.
- 공정 준비는 로봇 현재 위치부터 확인한다. 도구 보정 유효성과 양초 위치를 구별하고 측정 접근/후퇴도 사전 검사한다.
- 철사 고정 중 그리퍼 열기·자동 집기·반납·청소는 제외한다. 실패나 정지 미확인 뒤 자동 이동을 추가하지 않는다.
- 가공 중 힘은 접촉·이상 감시에 활용한다. 실제 홈 깊이·실물 품질의 직접 측정값으로 표시하지 않는다.
