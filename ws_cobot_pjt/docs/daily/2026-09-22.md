## 1. 하루 요약

9/22에는 9/21의 측정·미리보기 흐름을 바탕으로 REAL 실행 후보의 데이터 계약과 HMI의 별도 실행 요청까지 main에 반영됐다. 작업 순서는 **MEASURE → 원본 저장·스냅샷 BIND → 이미지 경로 생성 → 미리보기 → 별도 ExecuteProcess 요청 → 공정 최종 검사·실행 결과**다. HMI, `c2_path`, `c2_process`의 실제 ROS 코드를 이어 시험하는 가상 장치 실행기도 추가됐다.

코드의 REAL 실행 후보 생성과 가상 장치 통과는 현장 M0609의 연속 측정·조각 성공을 뜻하지 않는다. 실행 설정의 현장 승인값과 실제 로봇 검증은 별도로 필요하다.

## 3. 현재 동작과 실행 전 조건

- HMI는 `C2_PREPARATION_CONFIG`와 별도 `C2_EXECUTION_PROFILE` 또는 준비 설정 안의 실행 프로파일을 검사한다. 승인되지 않았거나 누락된 속도·가속도·가공 깊이·TCP·하중을 임의로 생성하지 않는다. 현장 준비 설정은 REAL 측정에 필수다. 실행 프로파일이 없으면 측정과 `test_only` 미리보기까지만 허용하고 BIND·공정 실행을 차단한다.
- 경로 노드는 스냅샷에 일치하는 REAL 실행 후보를 만들 수 있다. `test_only=false`와 `real_execution_allowed=true`는 후보 표시이지 조각 최종 승인 결과가 아니다. HMI는 원본 ID·해시·모드·작업 범위를 대조한다.
- 공정 노드는 별도 ExecuteProcess 요청에서 준비·경로·설정 동일성과 최신 관측값을 다시 검사하고, 실제 깊이·접근·이탈이 반영된 실행계획의 명시 waypoint에 대해 IK와 관절 범위를 검사한다. 점 사이 전체 궤적의 충돌이나 가공 품질을 보증하지 않는다.
- `PrepareWorkpiece.Result`에 절대 윗면 확인 여부를 나타내는 두 bool 필드가 PR #67에서 추가됐다. 기존 설치본과 새 공통 타입은 호환된다고 가정하지 않고 같은 커밋의 `c2_interfaces`를 빌드·배포해야 한다.
- 드릴 ON은 HMI의 수동 화면 확인이고, 그리퍼 개폐·드릴 전원 명령은 이 흐름에 포함되지 않는다. 정지 접수·취소 수락과 실제 정지 확인을 구별한다.

## 4. 당시 검증 기록과 한계

[가상 셀 기록](../VIRTUAL_CELL_20260922.md)은 실제 HMI·`c2_path`·`c2_process` ROS Jazzy 코드를 연결하고 측정·로봇 장치 경계만 모의 어댑터로 바꿨다. 정상 `SUCCEEDED`, IK 실패 `FAILED`, 모션 명령 실패 `FAILED`, 이동 중 정지 `STOPPED`를 기록했다. 사용자 도안은 303구간 `SUCCEEDED`였지만 모든 모션은 `MockRobotAdapter` 호출이다. 당시 기록에는 backend 135개 통과·4개 건너뜀, 공정 node/preparation 283개 통과·2개 건너뜀이라고 적혀 있다.

[REAL HMI 통합 기록](../HMI_REAL_INTEGRATION_FIXES_20260922.md)은 Jazzy 공통 타입 빌드, backend 163개 통과·6개 건너뜀, c2_path/c2_process 1030개 통과·5개 건너뜀을 기록한다. 후속 설정 정렬 단계에는 backend 192개 통과·6개 건너뜀, J6 관련 선택 시험에는 35개 통과·2개 건너뜀이라고 별도로 적혀 있다. **서로 다른 단계의 시험 수를 합산하지 않는다.** 이 일지 작성 중 재실행한 결과도 아니다.

실제 M0609와 드라이버를 통한 준비→BIND→경로→조각 전체 DDS 왕복, 실제 IK·간섭, 가공 깊이와 품질, 정지 소요시간은 위 기록으로 확인되지 않는다. 가상 셀의 정지는 실제 비상정지 성능 시험이 아니다. REAL 실행 프로파일의 수치와 현장 설정은 배포 환경에서 별도 확인이 필요하다.
