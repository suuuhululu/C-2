## 1. 오늘의 결과

**운영자 모니터·좌표 생성·공정 제어의 3개 노드 구조를 개발 기준으로 정리하고, 개별 구현과 검증을 진행했다.** 기존 Clay 코드·실행 안내를 main에 공유한 뒤 새 구조로 이관하기 위한 작업을 분리했다. 로봇 어댑터는 main에 병합됐고, 조각·청소는 기능 브랜치, 새 HMI와 아키텍처는 Draft PR에 있다.

Notion에는 9/17~18에 걸친 곡면 위치·칼끝 자세·역기구학·가상 재생 검증 결과와 YAML 설정 담당표가 추가됐다. GitHub에는 9/18 어댑터의 실제 이동·취소·접촉 시험 보고가 있다. **곡면 가상 재생, 어댑터 단위 실기, 새 3개 노드 전체 공정의 실기 완료는 서로 다른 상태**다. 전체 공정 통합과 원통 옆면 가공 품질 검증은 남아 있다.

이 일지는 원문 보고를 정리한 기록이다. 일지 작성 중 로봇을 구동하거나 팀원의 시험을 재실행하지 않았다. 수치에는 원문과 확인 범위를 붙였으며, 원본 bag·외부 작업용 코드·첨부 ZIP 전체는 이번 일지 작업에서 분석하지 않았다. 9/17 실험이 9/18에 GitHub에 병합된 경우에는 실험일과 게시일을 구분한다.

## 2. 공통 설계와 담당 경계

[PR #10](https://github.com/suuuhululu/C-2/pull/10)으로 인터페이스 안내·디렉토리·통신 계약을, [PR #11](https://github.com/suuuhululu/C-2/pull/11)로 팀·AI 작업 규칙과 세 ROS 패키지 개발 디렉토리를 main에 반영했다.

- 흐름: 이미지·설정 입력 → 경로 생성 → 미리보기 확인 → 별도 실행 요청 → 준비 검사·도구 집기·조각·필요한 청소·반납 → 결과·검사 기록.
- 고객용 웹앱·주문 대기열을 제외하고 운영자 모니터 중심으로 범위를 축소했다.
- 작업대와 대상은 등록한 고정 좌표를 사용한다. 매 작업 위치 스캔은 기본 공정에서 제외하지만 2D→3D 표면 매핑과 자세 계산은 필요하다.
- 그리퍼 한 장치가 도구를 집고 놓는다. 그리퍼·집기·조각·청소 파일마다 별도 ROS 노드를 만들지 않는다.
- 화면 입력은 mm·deg, 3D 경로는 m·quaternion `(x,y,z,w)`, 관절은 rad를 사용한다. 두산 API 단위·회전 표현 변환은 `robot_adapter.py`의 책임이다.

| 노드 / 영역 | 책임 | 9/18 자료에서 확인한 담당 |
|---|---|---|
| `monitor_gateway_node` / HMI·서버 | 요청 전달, 경로·상태 표시, 실행·알람·검사 기록 | 이수현 |

## 3. Notion — 곡면 경로·자세의 가상 검증

근거: [검증보고서: 2D→3D 좌표 변환 후 경로생성](https://app.notion.com/p/2D-3D-3df5211811398011a854d5be965b643f). 원문 기간은 **9/17~18**, 첨부명은 `2D->3D(세은).zip`이다. 아래는 본문에 보고된 결과이며 이번 일지에서 재실행한 결과가 아니다.

### 해결한 문제와 검증 범위

작업용 `rokey_gpt`에서 SVG → 2D 좌표 → 원통 위치·법선 → 칼끝 자세 → 역기구학(IK) → 가상 재생·충돌 기록 흐름을 구성했다. 초기의 칼 방향 문제를 회전 공식 하나로 단정하지 않고 다음 항목으로 나눠 수정했다.

- 가로 장착 칼의 접근축과 TCP 위치·회전 정의를 분리했다. 작업 모델은 TCP +X가 원통 안쪽, +Z가 아래를 향한다.
- ZYZ 회전 변환의 180° 경계 처리를 보완하고 독립 회전 계산과 비교했다.
- 첫 목표의 IK 초기값·탐색 시간을 조정하고, 손목 ±180° 경계에서 불필요한 약 358° 회전을 줄였다.
- 손가락–받침대 간섭에 대해 원통은 유지하고 도안 높이를 총 +6mm 이동했다. 도안 간 이동도 손목 회전 누적을 줄이는 방식으로 바꿨다.
- `job.json`으로 SVG와 원통 설정을 분리하고 재생의 마지막 응답까지 충돌 기록을 수집하도록 보완했다.

| 원문 시험 | 보고된 결과 | 해석·한계 |
|---|---|---|
| 접근축·회전행렬·플랜지 복원 | 수평 법선 1,000개 검사 통과 | 작업용 모델의 수치 검사 |
| ZYZ 변환 | 0°·180° 경계를 포함한 독립 비교 900개 통과 | 장착된 실물 도구 축 확인을 대신하지 않음 |
| TCP 모델 정합 | 전개 URDF와 설정 위치 차이 0.001mm 미만 | 실물 컨트롤러 TCP 등록 검증 아님 |
| 기존 SVG 비접촉 경로 | 목표 382개·보간 자세 5,120개, IK·상태 유효성 검사 통과 | 표면 바깥 경로이며 실제 음각 경로의 무충돌 판정 아님 |
| 신규 잎사귀 음각 경로 | 3D 목표 119개(펜다운 96), 재생·검사 626/626 완료 | 화면 없는 가상 실행·보고서에 기반한 원문 기록 |
| 잎사귀 접촉 기록 | 507개 샘플에서 `cylinder / hera_body` 접촉, 첫 침투 약 1mm | 507번의 독립 사고가 아님. 지정 깊이에 따른 칼 모델 접촉이며 절삭력·품질 검증 아님 |
| 최종 시험·빌드 | 시험 41개와 작업 패키지 빌드 통과 | 외부 작업용 `rokey_gpt` 결과. C-2의 `c2_path` 구현·빌드 완료와 구분 |

원문 시험편은 반지름 37.5mm·높이 200mm이며 칼 돌출 40mm는 가정값이다. 양초 68×150mm를 사용하는 공정 초안과 같은 설정으로 합치지 않는다. 가상 진단 모드가 접촉 후에도 재생을 계속한 것을 충돌 해소로 기록하지 않는다. 재료를 실제로 깎는 시뮬레이션도 아니다.

실물 돌출 길이·장착 회전·컨트롤러 TCP 일치, 홈에서 첫 목표까지 접근, 실제 저속 동작·절삭력·품질, 보간 샘플 사이의 연속 충돌 확인은 원문에서도 미완료로 남아 있다. 첨부 ZIP의 존재는 확인했지만 이번 커밋으로 C-2 실행 패키지에 가져오지 않았다.

## 4. GitHub — 로봇 어댑터와 조각·청소

### 이시율: 공용 로봇 어댑터 — main 반영

[Issue #12](https://github.com/suuuhululu/C-2/issues/12)·[PR #13](https://github.com/suuuhululu/C-2/pull/13), 구현 커밋 [`e347e5f`](https://github.com/suuuhululu/C-2/commit/e347e5f4a7da095ed7c98f8360267b7463233250). 기존 Clay의 로봇 연결 기능을 새 공정 내부 공용 `robot_adapter.py`로 이관했다.

직선·곡선 이동, 접촉 탐색, 정지, TCP·하중 선택 및 재조회, 도구 오프셋, 상태 관찰과 모의 어댑터를 제공한다. 내부 결과로 완료·실패·정지·미확인을 구분하며 새 ROS Topic/Service를 추가하지 않았다. 집기·반납·조각·청소가 같은 어댑터를 사용하도록 했다.

다음은 **PR 작성자의 9/18 실기 보고**다. 보고 장비는 M0609+RG2, DART 2.12.1, 실행 파일은 `test/real_adapter_check.py`다. 이 일지 작성자는 원본 bag를 직접 분석하지 않았으며 아래 수치를 새 공정의 승인된 실행값으로 지정하지 않는다.

| 시험 | PR에 보고된 결과 | 남은 확인 |
|---|---|---|
| TCP·하중 선택 | `GripperDA_v1` / `ToolWeight_1` 선택·재조회 일치 | 실물 도구 장착·파지 확인과 별개 |
| 위로 20mm 이동 | 위치 오차 1.2~1.9mm | 반복성·전체 자세 오차·공정 허용 오차 대조 |
| 이동 중 취소 | 60mm 이동 중 1.5초에 취소, 약 1.6초에 STOPPED, 10mm 위치에서 정지 후 STANDBY | 해당 시험 조건의 결과. 모든 상황의 정지 성능 보장 아님 |

PR의 bag 식별자는 `bag_adapter_0918_1821`, `1833`, `1835`, `1836`이며 이시율 PC의 `ws_dsr`에 있다고 보고됐다. 접촉 높이 기록 1829(175)와 1836(232)의 차이도 원인 미확인으로 남아 있다. 당시 실제 코드·최종 수정 커밋·bag별 설정을 연결해 보완해야 한다.

모의 시험 7개 통과는 PR 기록으로 확인했다. `c2_process`의 패키지 빌드 설정이 없어 colcon 빌드는 미수행이며, 실행 PC의 준비된 환경에서 개별 스크립트로 시험한 결과다. PR의 RG2·DART·TCP 표기는 해당 시험 보고의 조건으로만 인용한다. 모든 PC의 설치본·배선·피드백이 확인된 것으로 확대하지 않는다.

### 이시율: 조각·청소 초안 — 기능 브랜치 반영

[Issue #14](https://github.com/suuuhululu/C-2/issues/14)·[PR #15](https://github.com/suuuhululu/C-2/pull/15), 구현 [`885ccfa`](https://github.com/suuuhululu/C-2/commit/885ccfa8e7dbf39c92a3fbd1d386849c5b22a8de). `engraving.py`·`cleaning.py`와 모의 시험을 추가했다.

- 조각: 경로 스키마·단위·구간·프로파일을 검사한 뒤 APPROACH/CUT/TRAVEL/RETRACT를 실행한다. 접촉 탐색 방식과 고정 깊이 방식을 구분하고 취소·실패 시 다음 구간을 시작하지 않는다.
- 청소: 설정된 청소면 접근 → 접촉 → 위로 훑기 1회 → 이탈 → 호출자가 지정한 재진입 위치 복귀 흐름을 둔다.
- 원문 시험: 모의 어댑터 11개 통과. 정상·입력 거절·실패 후 진행 차단·취소·접촉 미검출·청소·단위 변환 등을 포함한다. 실기·가상 브링업은 미수행이다.
- `ExecutionContext`와 청소 설정의 일부 필드가 임시다. 샘플 경로·현장 좌표·가공 프로파일·픽업 종료 자세와 연결해야 한다.

**PR #15는 main이 아니라 `feat/12-robot-adapter`에 병합됐다.** 브랜치 결과는 [`4b6416d`](https://github.com/suuuhululu/C-2/commit/4b6416dff6cfb31218d9ec28739812079f3fe68e), 기준 main에는 두 모듈이 없다. 확인 시점 Issue #14도 열려 있다. PR의 병합 표시만으로 전체 구현·통합 실기 완료로 처리하지 않는다.

| 0° 방향·허용 각도 | 이시율·노홍동 합의 | 경로 분할·조각 검증 |
| 청소면 위치 | 김세은과 확인 | 이시율의 청소 모듈 |
| `tools.yaml` 도구 ID·집기·반납·TCP·하중 | 김세은 | 도구 순서·그리퍼·로봇 어댑터 |
| 재료별 가공·청소 프로파일 | 이시율 | 조각·청소 모듈 |
| 설정 버전 | 변경자가 갱신 | 생성 경로와 실행 시 설정 대조 |

현재 자료에서 다음 차이가 확인돼 통합 전에 대조해야 한다.

1. **공구 접근축:** 곡면 가상 검증은 TCP +X가 안쪽을 향하지만 PR #13·#15의 합의 기록은 TCP +Z가 안쪽이라고 한다. 가로 칼 모델과 송곳 모델의 서로 다른 정의를 같은 quaternion으로 해석하지 않도록 `tool_id`·장착 회전·경로 자세 기준을 명시해야 한다.
2. **공구 끝과 제어기 TCP:** PR은 기본 그리퍼 TCP와 소프트웨어 돌출 보정을 사용하고, 가상 검증은 칼끝 링크 `hera_tcp`를 사용한다. 중복 오프셋 적용을 막고 동일 목표의 변환을 양쪽 담당자가 대조해야 한다.
3. **시험편·받침대:** 가상 검증은 반지름 37.5mm·높이 200mm, 공정 초안은 양초 지름 68mm·높이 150mm다. Notion에는 받침대 시험 20mm·최종 115mm가 함께 적혀 있다. 값마다 시험/최종·실측/가정·설정 버전을 붙여야 한다.
4. **고정 좌표와 측정:** Notion의 스캔 담당은 좌표 등록·현장 확인 업무와 연결해 해석해야 한다. 이를 근거로 매 작업 위치 탐색을 기본 공정에 다시 넣지는 않는다.
5. **그리퍼 완료:** PR에는 직접 파지 피드백이 없고 픽업 후 접촉 탐색으로 확인하는 흐름이 보고돼 있다. 명령 접수·닫힘·실제 도구 확인을 구분하는 완료 조건을 공통 상태와 맞춰야 한다.

위 항목은 자료 대조에서 드러난 후속 확인 사항이며, 이 일지에서 팀 계약·현장 설정을 새로 확정한 것은 아니다.

## 6. 이수현 — 시스템 아키텍처·설명 자료·HMI

### 시스템 설명 자료와 Clay 보관

[PR #16](https://github.com/suuuhululu/C-2/pull/16), 커밋 [`30e81a7`](https://github.com/suuuhululu/C-2/commit/30e81a73c34e0989cf0617b41acbefebe4716841)에 편집 가능한 **8페이지 draw.io**를 추가했다. 전체 구조, Action 입출력, 정지·상태·이벤트, 내부 모듈, 파일·좌표·단위, 정상·오류 흐름, 어댑터와 실제 구현 차이를 정리했다.

팀원이 각자 인터페이스 계약을 기준으로 AI와 개발할 때 전체 송수신 구조를 이해하도록 설명 자료도 준비했다. Notion 팀 페이지에서 `C2_시스템_송수신_설명_v2.pptx`, `TEAM_QUICK_REFERENCE.md`, `C2_SYSTEM_ARCHITECTURE.drawio` 첨부를 확인했다. 로컬에는 13장 발표 자료·팀장 설명 대본·빠른 참고표가 있다. 첨부 존재와 자료 작성은 확인했으며, 팀 설명회 실시·참석·이해도 검증까지 완료했다고 기록하지 않는다.

기존 `clay_carving`·`clay_hmi`·전용 실행 안내 32개 파일은 사용자 요청에 따라 저장소 밖 `local_file/clay_archive_2026-09-18/`에 복사하고 원본과 SHA-256을 대조한 뒤 PR #16 브랜치에서 제거했다. 과거 Git 이력과 새 로봇 어댑터는 보존했다. **PR #16은 Draft·미병합이므로 확인 시점 main에는 기존 Clay 코드가 남아 있다.** [보관·복구 기록](https://github.com/suuuhululu/C-2/blob/30e81a73c34e0989cf0617b41acbefebe4716841/ws_cobot_pjt/docs/LEGACY_CLAY_ARCHIVE.md).

### 운영자 HMI·서버·DB 초안

[PR #17](https://github.com/suuuhululu/C-2/pull/17), 커밋 [`87cbe23`](https://github.com/suuuhululu/C-2/commit/87cbe23d2e1956613c7f1c6c3dacc90ed4741841), `codex/hmi-monitor-simulation`에 게시된 Draft다.

- React HMI, FastAPI 서버, 새 SQLite 저장소, 모의 상대와 ROS 클라이언트 연결 코드를 추가했다.
- 첨부 → 배치 → 2D/3D 미리보기 → 모의 실행 → 관제·알람·이력·검사 저장 흐름을 구성했다.
- 요청 중복·파일 해시·재시작·정지 미확인·늦은 응답을 다루고 DB 잠금 중에도 정지 전달을 우선하도록 했다.
- 전개면·원기둥에 구간별 예정·진행·가공 확인·실패·미확인을 구분한다. 이동 완료와 가공 판정, 최종 검사 합격은 별개다.

PR에는 API/DB 시험 15개, TypeScript 검사·Vite 빌드, 브라우저 모의 흐름 확인 통과가 기록돼 있다. **현재 구간 판정은 모두 모의 데이터이며 센서·로봇과 연결하지 않았다.** 이미지 변환은 `c2_path`의 책임이며 HMI의 고정 중심선 샘플을 실제 SVG 변환 결과로 취급하지 않는다.

실제 `c2_interfaces` 타입, 경로 파일을 읽는 `artifact_loader`, 원본 waypoint와 표시 점의 대응, 구간 품질 근거·시각·quality 계약은 후속이다. `mock-preview/1` 등은 시험 형식이며 공통 ROS 계약의 확정판이 아니다. ROS 통합·실기 시험은 미수행이다. [구현·인계 안내](https://github.com/suuuhululu/C-2/blob/87cbe23d2e1956613c7f1c6c3dacc90ed4741841/ws_cobot_pjt/docs/HMI_MONITOR_IMPLEMENTATION.md).
