# 촬영 조건·연결 경계 — 오전 공유용

2026-10-06. 아래는 실제 촬영에 적용할 조건과 확인 항목입니다.
이 ZIP은 합성 callback 자료이며 조건을 자동 감지하거나 장치 신호를 구현한 코드가 아닙니다.

## 촬영 가능한 조건

| 조건 | 확인 책임·현재 상태 |
|---|---|
| 활성 완료 확인 check와 목표 after | Backend가 제공. 촬영 묶음 시작 시 check_id/observation_seq 고정 |
| 검증된 관측 자세로 이동 후 실제 정지 | Controller 담당 확인. B는 이동 명령·정지 검출을 구현하지 않음 |
| 이번 확인에 필요한 영역의 가림 해소 | B가 판별 가능 여부 확인. 손 감지 방식·신호·임계값은 미정 |
| 같은 조립 상태의 View 묶음 | 촬영 중 사람 조립·블록 이동·STOP·check 변경 시 기존 묶음으로 완료 확정하지 않음 |
| 촬영 pose에 유효한 Camera→Board 보정 | 실측 보정 version과 pose 대응 확인 필요. 기본 identity를 적용하지 않음 |
| RGB·정렬 Depth·intrinsics·scale·시각 관계 유효 | 단위·크기·정렬·Depth 누락 확인. Viewer 캡처만으로 층 판정하지 않음 |

사람 이탈은 단순 버튼 입력만으로 실제 확인했다고 주장하지 않습니다.
완료 확인 시점은 B가 판단하며 매 Step HMI 완료 버튼을 필수로 추가하지 않습니다.
정지 후 안정 프레임 수·대기 시간·timeout·동기 허용 오차·Depth/confidence 임계값은
실측 후 정할 값입니다. 이 자료에는 검증되지 않은 수치를 넣지 않았습니다.

## View와 결과 구성

- V0 중앙 상부, D1 북서, D2 북동, D3 남동, D4 남서가 시험 후보입니다.
  실제 필요한 최소 View는 가림·검출률·촬영/이동 시간을 측정해 정합니다.
  모든 Step에서 다섯 View 촬영을 필수로 강제하지 않습니다.
- 이동 중 프레임을 완료·전달판 비움 증거로 사용하지 않습니다.
- 여러 View를 하나로 반환하면 묶음 시작에 고정한 check/seq를 유지합니다.
  같은 블록은 중복 집계하지 않고 View 충돌은 판별 불가 사유로 반환합니다.
  실제 다중 View 융합은 이 ZIP에 구현돼 있지 않습니다.
- visible_blocks는 이번에 확인한 실제 블록만입니다. 추적 유지값을 섞지 않습니다.
- verified_regions는 실제 해당 layer의 점유 상태를 확인한 x/y/width/height 영역입니다.
  가림·Depth 부족·시야 밖을 제외하고 진단 사유로 설명합니다.
- 현재 목표가 읽히면 OK이며 Expected와 다를 수도 있습니다.
  현재 목표를 읽지 못하면 UNOBSERVABLE과 reason으로 반환합니다.
  확인된 아래층만 가린 것은 기록 유지 대상이며 그 자체가 전체 보류 근거는 아닙니다.

## 전달판

조립판과 별개입니다. 현재 확인 문맥의 EMPTY/OCCUPIED/UNOBSERVABLE과 사유를 전달합니다.
미수신·대기는 null이며 EMPTY로 추정하지 않습니다. 예전 EMPTY 프레임을 새 전달에 재사용하지 않습니다.
자료의 `proposed_diagnostics.delivery_board` 위치와 진단 수신 경로는 수현님과 맞출 제안입니다.
Observed의 여섯 필드에 전달판 상태를 임의 추가하지 않습니다.

## 남은 연결 확인

BLOCKER: 실제 callback 함수·별도 진단 수신 경로·실측 보정·카메라 안정 조건 미검증.
REQUIRED CHANGE: 수현님이 JSON 입력을 소비 검사에 넣고 진단 전달 위치를 확인;
장치 담당과 촬영 pose·정지·보정·데이터 품질을 실제 시험.
AFFECTED INTERFACE: 완료 확인 요청, Observed callback, 추적 피드백, 전달판 진단.
REASON: 합성 예시·계약 문서의 준비는 실제 모듈·장치 연결 성공과 다름.
