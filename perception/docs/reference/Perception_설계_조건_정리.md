# Perception 파트 설계 조건 정리

작성일: 2026-10-06  
누적 수정일: 2026-10-08  
적용 범위: Day4(2026-10-08)까지의 1PC MVP  
문서 성격: 대화에서 정한 설계 조건과 최신 공통 계약을 정리한 문서. 구현 완료·장치 성능 검증을 의미하지 않습니다.

## 1. 설계 목표와 담당 경계

Perception(B)은 사람이 조립한 실제 블록의 종류·색상·위치·층수·방향을 관측하고, 판별 가능 여부와 함께 Backend에 전달합니다.

| 담당 | 책임 |
|---|---|
| A — Planning & Replanning | 사람의 조립 순서·선행 조건·재계획 검증 |
| B — Perception | 촬영 시점·필요 관측점·블록 인식·관측 품질·Observed 출력 |
| C — Adaptation / AI Decision | 키워드의 목표 Design 생성·차이에 대한 사람 의도 해석·목표 수정 |
| D — Robot Execution / HRI | Backend의 Current·Expected·비교·완료/보류, 로봇 제어·HMI·통합 |

- B가 LLM의 추상적 물체 생성이나 조립 순서를 결정하지 않습니다.
- B는 실제 관측을 출력하고, Backend가 Current를 채택하고 목표와 비교합니다.
- 로봇의 관측 자세·joint/TCP·경로·정지 확인은 D Controller 담당입니다. B가 저수준 로봇 동작을 생성하지 않습니다.
- 로봇은 Supply Board에서 전달 슬롯/전달판으로 블록을 운반하고, 사람이 Assembly Board에 배치·체결합니다. 전달판과 조립판은 다른 영역입니다.
- 로봇이 조립판에 직접 블록을 결착하는 공정은 최종 시연 방향이며 이 문서의 Day4 전달형 MVP와 구분합니다.

## 2. 장비와 MVP 범위

- M0609의 6번 조인트에 장착된 RealSense D435i 한 대를 사용합니다.
- 사용자가 설명한 기본 장착 시점은 바닥을 수직으로 바라보는 방향입니다. 실제 광학축·장착 변환은 보정으로 확인합니다.
- Assembly Board의 RGB와 Depth를 함께 촬영합니다. 일반 RGB 영상만으로 Depth 중앙값을 얻을 수는 없습니다.
- Day4 공급 동작은 사전 검증된 고정 슬롯 좌표를 사용합니다. Supply Board 비전 기반 탐색은 후속 확장입니다.
- 고정 웹캠을 이용한 단독 층수 판별은 현재 주 인식 경로에 포함하지 않습니다.
- Day4는 1PC, Vision callback 연결, Qt HMI, 주요 이벤트 JSONL 기록을 기준으로 합니다.

## 3. 블록과 보드 좌표

| 항목 | 조건 |
|---|---|
| 보드 | 24×24 stud |
| stud 간격 | 실제 보드 직접교시 측정 기준 약 16mm. 최종 보정값은 TCP/접촉점 확인 후 확정 |
| x, y | 정수 0~23, stud 단위 |
| 위치 기준 | 블록 footprint의 최소 x/y 스터드 중심. 실물 외곽 모서리와 구분 |
| 보드 원점 | 사용자가 지정한 왼쪽 아래 빨간 표시의 기준 stud가 (0,0) |
| 축 | 공통 계약 기준 +X 오른쪽, +Y 위. 실제 보드에서 방향을 확인하고 보정 |
| 층 | layer 1~4, 보드 위 첫 층이 1 |
| 블록 종류 | `2x2x1`, `2x3x1` |
| 색상 | `yellow`, `blue` |
| 방향 | 2×3: 0 또는 90도. 2×2: 대표값 0도 |
| 2×3 footprint | 0도: X폭 2/Y폭 3, 90도: X폭 3/Y폭 2 |

블록의 기준점뿐 아니라 전체 footprint가 보드 안에 있어야 합니다. X폭 w, Y폭 h이면 `0 ≤ x`, `x+w-1 ≤ 23`, `0 ≤ y`, `y+h-1 ≤ 23`을 만족해야 합니다. 범위를 벗어난 실제 관측을 목표 좌표로 임의 보정하지 않습니다.

### 스터드 간격과 보드 실측 기준 — 2026-10-08 수정

- 세은님이 동일 보드의 가장 바깥쪽 stud 중심을 직접교시로 측정한 **약 16mm 간격**을 설계·보정 정합성의 기준으로 채택합니다. 기존 `calibration.json`의 `pitch_mm: 17.0`보다 실제 보드 측정 근거를 우선합니다.
- A/B/C/D 측정점 역시 같은 보드의 가장 바깥쪽 네 모서리 stud 중심입니다. 판의 외곽 모서리나 stud 가장자리가 아닙니다. 원점과 +X/+Y는 실제 보드에 표시된 방향을 유지합니다.
- 24개 stud의 첫 중심부터 마지막 중심까지는 **23칸**입니다. 약 16mm 기준 중심 간 길이는 **약 368mm(23×16)**이며, 기존 **391mm(23×17)**를 현 보드의 실측 길이로 사용하지 않습니다. 368mm는 판 외곽 치수가 아닙니다.
- 약 16mm는 현재 측정에 근거한 기준이며 정밀 보정 완료를 뜻하지 않습니다. TCP 등록값과 닫힌 그리퍼 끝단의 실제 접촉점 일치, X/Y 양축의 중심 간 거리와 반복 측정을 확인한 뒤 최종 간격·보정값을 확정합니다.
- 실행용 `pitch_mm` 또는 `stud_pitch_m`은 확인된 실측 결과로 맞춰야 합니다. 기존 17mm로 산출한 보드 변환·좌표·투영·오차는 재검증 대상이며, 간격 숫자만 교체했다고 전체 보정이 끝난 것으로 보지 않습니다. 원자료는 보존하고 새 보정의 버전/ID를 구분합니다.
- 이번 수정은 문서 기준의 갱신입니다. 실행용 보정 JSON·설정·기존 측정값을 자동 덮어쓰지 않습니다.

### 블록 좌표의 격자 정합성 검사

- 블록의 왼쪽 아래 스터드 기준점(최소 x/y 스터드 중심이며 블록 외곽 모서리와 구분)을 보드 좌표로 변환한 뒤, 가장 가까운 정수 Grid 좌표와의 차이를 검사합니다.
- 현재 **임시 시험 임계값은 X·Y 각각 0.25칸 이내**입니다. 스터드 간격 약 16mm 기준으로 각 축 약 4mm에 해당합니다. 두 축 모두 기준을 만족해야 하며, 대각선 거리 4mm 기준을 뜻하지 않습니다. 최종 간격이 확정되면 mm 환산값도 그 값으로 계산합니다.
- 임계값 이내이면 정수 좌표 후보로 처리하고, 연속 프레임 안정성 검사 후 표시합니다. 격자 정합성 통과만으로 종류·층·방향·조립 완료까지 확정하지 않습니다.
- 어느 한 축이라도 임계값을 초과하면 정수 좌표로 강제 확정하지 않고 `UNKNOWN` 및 `position_off_grid` 사유를 표시합니다.
- 이 기준은 **보드 캘리브레이션 검증 임계값 2mm와 별개**이며, 실제 위치·관측점·층별 시험 후 운영값을 확정합니다. 0.25칸은 임시 시험값이지 검증된 위치 정확도나 운영 허용 오차가 아닙니다.
- 인식률을 높이기 위해 임계값만 완화하지 않습니다. 보정 정확도, 윗면·옆면 분리, Depth 품질을 먼저 확인합니다.
- 이 검사는 고정된 보드 좌표에서 수행하고, 상대 좌표 변환으로 격자 오차를 숨기거나 목표 위치에 맞춰 보정하지 않습니다.

### 자유 시작점 요구사항 — 고정 기준점 계산 구현, 공통 연결 필요

- 사람의 첫 블록 위치를 기준으로 전체 목표를 평행 이동하는 방향을 요구사항으로 정리합니다.
- 보드 원점은 고정하고, 목표 블록들의 상대 간격·층·종류를 유지한 채 같은 Δx/Δy를 적용합니다.
- 첫 블록과 Design의 어느 기준 블록을 대응시킬지, 기준점 확정 시점·전달 형식·Owner는 A/C/D와 협의해야 합니다. 현재 공통 계약에 구현 완료된 기능으로 간주하지 않습니다.
- 전체 완성품의 모든 footprint를 검사합니다. 시작점이 보드 안에 있어도 완성품이 밖으로 나가면 진행할 수 없습니다.
- 범위 초과 시 Backend가 진행을 보류하고 HMI가 사유와 필요한 조치를 안내하는 방향입니다. 유효 시작 영역·초과 부분 강조·이동 방향 표시는 제안이며 상세 화면 표현은 미확정입니다.
- 전체 목표의 회전까지 허용할지는 미확정입니다. 평행 이동과 자동 회전을 혼동하지 않습니다.
- 2026-10-08 사용자 확인: 첫 배치 위치를 기준점으로 한 번 고정하며 다음 블록마다 따라 움직이지 않습니다. `perception_mvp/assembly_anchor.py`가 전체 목표 평행 이동·범위 검사·관측의 내부 상대 좌표 변환을 제공합니다. 기존 실제 상태는 보드 좌표를 유지하며 같은 기준점에서 표시합니다. 공통 Observed 필드는 변경하지 않았고 실제 Backend/Plan/HMI 연결은 별도입니다.

## 4. 확정 인식 알고리즘

**YOLO Segmentation + D435i Depth/Grid 검증 + 다중 시점 관측 + 이전 조립 상태 추적**을 사용합니다.

| 구성 | 역할·주의점 |
|---|---|
| YOLO Segmentation | 보이는 블록의 instance mask와 종류·색상 인식. 가려진 아래층을 직접 복원하지 않음 |
| Depth/Grid 검증 | 보드 좌표계의 위치·footprint·방향·높이·층수 검증. 반사·유효 Depth 부족에 영향받음 |
| 다중 시점 관측 | 서로 다른 방향의 실제 증거를 통합해 가림·반사 보완. 이동 시간과 시점 간 장면 변화 관리 필요 |
| 이전 상태 추적 | 단계별 추가·제거·이동 검토, 확인된 아래층 정보 유지. 관측 누락만으로 삭제하지 않음 |
| OpenCV 영상 변화 검출 | 변화 영역과 진단 화면 강조를 제공하는 보조 기능. 완료 판정이나 주 인식을 대체하지 않음 |

같은 색 블록이 포개진 경우 보이는 블록을 YOLO로 인식하고, 높이와 이전 채택 상태를 함께 검토합니다. 확인할 수 없거나 시점 결과가 충돌하면 내부적으로 `UNKNOWN`으로 관리하며 목표를 추정해 채우지 않습니다. 필요한 대상의 판별이 불가능하면 공통 반환은 `UNOBSERVABLE`과 사유입니다.

Voxel 융합은 복잡한 3D 구조를 표현해야 할 때 검토할 확장 기능이며 Day4 필수가 아닙니다. 확정된 알고리즘 조합이 실제 정확도를 보장하는 것은 아닙니다.

### 팀장 제안 추가 채택 — 전체 보드의 실제 배치 인식

- 조립판 전체의 개별 블록 인식 → RGB-D 배치 계산 → 이전 관측과 대응·재확인 → 실제 확인 결과만 Backend에 반환합니다. 기존 알고리즘을 폐기하는 것이 아니라 관측 범위와 책임을 명확히 합니다.
- Backend의 `after`는 반드시 확인할 목표를 안내하는 정보이며 관측을 목표 주변으로 제한하는 ROI가 아닙니다. 목표 (3,5)에 놓아야 할 블록이 실제 (15,15)에 있으면 실제 위치도 검출·반환해야 합니다.
- 층은 Step 순서와 무관하게 실제 보드 기준 높이로 계산합니다. 3층 작업 후 다른 위치의 1층 작업도 처리할 수 있어야 합니다.
- 전후 차분과 추적은 추가·제거·이동 후보를 찾는 보조 수단입니다. 변화가 없더라도 현재 배치를 재확인합니다.
- 모든 stud를 개별 학습하기보다 블록 instance 영역·윗면 경계와 알려진 형상을 우선 활용합니다. 사선 mask의 옆면을 윗면 높이 계산에 혼합하지 않도록 검증합니다.
- 이번에 완전히 가려진 아래층은 과거 기록으로 유지하며 새 관측으로 반환하지 않습니다. 가려진 동안 사람이 아래층을 바꾸지 않는다는 Day4 전제와, 실제 변경까지 관측 가능한지를 구분합니다.
- 우선 시험은 실제 1~4층 구분, 같은 색 맞닿은 블록 분리, 목표 밖 배치·기존 블록 이동입니다. YOLO 라벨링 전에는 블록을 띄워 놓고 실시간 OpenCV로 좌표·높이 계산을 시험할 수 있지만, 이를 밀집 장면의 YOLO 인식 검증으로 간주하지 않습니다.

### 블록 좌표 계산·검증 방식

**주 계산은 현재 RGB-D 관측으로 수행하고, 아래층의 확정 좌표는 보조 검증에 활용합니다.**

1. 현재 영상에서 블록을 검출하고, 옆면·배경을 제외한 윗면의 유효한 정렬 Depth를 사용합니다. 높이대 선택만으로 항상 윗면이 정확히 분리된다고 보장하지 않고 평면·형상·Depth 품질을 검증합니다.
2. 카메라 내부 파라미터로 3D 역투영하고 관측점별 Camera→Board 보정값으로 윗면을 보드 기준 3차원 좌표로 변환합니다. 높이에 따라 사선 영상에서 위치가 이동해 보이는 효과는 이 3D 변환으로 반영합니다. 높은 블록에 보드 평면용 2D 변환만 적용해 좌표를 확정하지 않습니다.
3. 블록 크기·방향과 실측 stud 간격을 이용해 **블록의 왼쪽 아래 스터드 중심(최소 x/y)을 기준으로 `(x,y)`**를 계산하고, 보드 기준 높이로 층을 검증합니다. 영상 중심·Step 목표·이전 Step 층에서 값을 추정해 채우지 않습니다.
4. 격자 정합성·연속 프레임 안정성·전체 footprint를 검사하고, V0 → D1 → D3 결과를 동일 보드 좌표계에서 통합·교차 검증합니다.
5. Backend가 이전에 채택한 아래층 좌표는 위층 위치 후보와 적층 정합성 확인에 활용합니다. **아래층 좌표를 위층에 무조건 복사하지 않습니다.** 서로 다른 크기·방향·부분 겹침으로 위층 기준점이 다를 수 있으며, 실제 관측과 충돌하면 목표나 아래층 좌표에 맞춰 강제 보정하지 않습니다. 지지 관계의 유효성·진행 판단은 A/D 책임과 구분합니다.
6. Depth 부족·보정 문제·시점 간 충돌 등으로 필요한 확인이 부족하면 내부 `UNKNOWN`과 사유로 처리합니다. 필요한 대상 판단 불가는 공통 `UNOBSERVABLE`, 장치/문맥 실패는 별도 실패 경로로 반환합니다. 가려진 아래층 기록은 미검출만으로 삭제하지 않습니다.
7. 계산 결과는 클릭 없이 실시간 화면에 표시합니다. 정수 좌표는 안정성 검사 이후 후보로 표시하고, 최종 Current 채택·조립 완료·다음 진행은 Backend가 수행합니다. 실시간 후보 표시를 Backend 채택 완료로 해석하지 않습니다.

**구현·검증 상태(2026-10-08):** OpenCV 시험 코드 `perception_mvp/opencv_live.py`에는 윗면 후보 추출·보드 3D 변환·크기/방향 기반 기준점 계산·격자/안정성 검사가 반영되어 있습니다. 분리된 블록 대상의 진단 후보 계산이며, 아래층 확정 좌표 연계와 실제 다중 시점·1~4층 정확도 검증은 아직 필요합니다. 보드 평면 기반 검색 ROI가 높은 층·사선에서 블록을 누락하지 않는지도 시험해야 합니다. 실제 성능 검증 완료나 전체 관측 자동 연결 완료를 의미하지 않습니다.

### 층별 높이 증가량 — 임시 설계 기준

| 적층 수 | 블록 묶음 높이 | 직전 층 대비 증가량 |

| 1층 | 22 mm | — |

- 위 수치는 블록 묶음 아랫면부터 맨 위 스터드 윗면까지이며 보드 기준 높이와 다릅니다. 첫 층까지 20mm로 바꾸거나 층수를 단순히 Depth/20으로 계산하지 않습니다.

## 5. OpenCV 색상 구분 → YOLO 학습

1. 실제 장비·관측점·조명에서 원본 RGB와 정렬 Depth, 보정·촬영 정보를 수집합니다.
2. OpenCV로 노랑·파랑 영역을 먼저 구분하여 라벨링 준비를 보조합니다.
3. 사람이 블록별 instance mask와 종류를 확인하고 수정합니다. 같은 색의 맞닿은 블록을 하나의 객체로 자동 확정하지 않습니다.
4. 다음 네 클래스로 원본 RGB 기반 YOLO Segmentation을 학습합니다.
5. 별도 평가 장면에서 mask·클래스와 Depth/Grid 검증 성능을 확인합니다.

| 클래스 | 의미 |
|---|---|
| `yellow_2x2` | 노란색 2×2 |
| `yellow_2x3` | 노란색 2×3 |

- 단독 블록뿐 아니라 실제 조립 중인 장면도 포함합니다. 모든 키워드의 모든 조립 순서를 촬영할 필요는 없습니다.
- 단계별 조립 영상은 상태 추적·가림·완료 확인 시험에 활용합니다.
- Depth는 위 네 클래스의 일반 RGB segmentation 학습 입력이 아니라 촬영 기록 및 후단 검증 근거입니다.
- OpenCV 색상 분리는 보조이며, 배경 제거 이미지로만 학습하고 원본 영상으로 추론하는 입력 불일치를 만들지 않습니다.
- 동일 조립 장면의 연속 프레임과 여러 View는 같은 학습/검증/시험 분할에 묶어 데이터 누수를 방지합니다.
- 손 감지는 블록용 네 클래스와 별도 기능입니다.

## 6. 관측점과 실측 조건

| 관측점 | 현재 채택 방향 |
|---|---|
| V0 | 상부 |
| D1 | 북서 대각 방향 |
| D3 | 남동 대각 방향 |

- 현재 관측은 **V0 → D1 → D3 세 점**입니다. 이전 대각 4점 구상에서 D2·D4를 제외했습니다. 연속 360도 회전이나 8개 관측점은 필수가 아닙니다.
- 방향명은 보드 기준으로 대응시킵니다. 실제 로봇 도달성·그리퍼/케이블 간섭·시야·안전성을 검증한 뒤 자세를 확정합니다.
- 더 줄이는 적응형 관측은 후속 시험안입니다. 현재 확정된 세 점 사이클을 시험 없이 자동 생략하지 않습니다.
- 대각 시점을 포함해도 모든 블록이 보인다는 보장은 없습니다. 관측점을 줄여도 신뢰도가 그대로라는 보장이나 기존 대화의 추정 퍼센트를 실측 성능 수치로 사용하지 않습니다.
- 실제 joint 값, TCP 위치/자세, 카메라 장착 변환, Camera→Board 변환, 카메라 내부 파라미터, Depth scale, stud 간격, 층별 상면 높이, 거리·화각을 측정·기록합니다. 임의 숫자를 실행값으로 넣지 않습니다.
- 원본 RGB·원본 Depth·RGB 정렬 Depth를 보존하고 View·촬영 시각·해상도·카메라 내부 파라미터/왜곡·Depth scale·보정 ID·실제 로봇 자세·요청 ID/순번을 대응시킵니다. 일반 사진 파일에 모든 촬영·로봇·보정 정보가 자동 저장된다고 가정하지 않습니다.
- 사선 Depth의 중앙값을 그대로 보드 높이로 해석하지 않습니다. 유효 Depth를 3D 역투영하고 보드 좌표계로 변환한 높이로 층을 검증합니다.

## 7. 관측 사이클 — 손 진입·이탈 조건

관측 자세는 다음 사용자 제공 기록을 사용하되 Robot 담당이 좌표계·단위·TCP/tool·자세 표현·안전 경로를 확인한 뒤 제어 코드에 유지합니다. B는 View ID와 대응하는 실측 Camera→Board 변환을 사용합니다. 이 표는 안전·도달성 검증 완료를 의미하지 않습니다.

| View | posx | posj |
|---|---|---|
| V0 | `[444.5, 17.2, 365, 96, -177.3, 94.4]` | `[3.8, 18.3, 40.5, -3.1, 121, 0.4]` |
| D1 | `[161.2, 243.2, 210, 150.1, -139, -90.2]` | `[95.5, -0.2, 101.2, -33.5, 103, -145.8]` |
| D3 | `[513.25, -160.9, 327.4, 78.1, 153.9, 60.8]` | `[-33.5, 38.5, 21.1, 30.9, 126.5, -33.7]` |

위 좌표는 2026-10-08 사용자가 제공한 최신 관측 자세로 교체한 기록입니다. 이전 자세로 구한 View별 Camera→Board 변환을 새 자세에 그대로 적용하지 않습니다. 각 새 자세에서 보정·시야·층 판별·오버레이 투영과 안전 이동 경로를 재확인해야 합니다.

촬영은 지정 자세에서 정지해 수행합니다. 자세 오차를 무조건 허용하지 않고 변환·투영·Depth 검증의 유효성을 확인합니다. 카메라 화면이 회전·기울어져 있어도 실제 보정으로 대응할 수 있으나, 같은 View의 이전·현재 비교에는 동일 자세와 검증된 정렬이 필요합니다.

**전달판에 블록 놓기 → V0 복귀·정지 → 사람이 블록을 가져와 조립·손 진입/이탈 감지 → 연속 이탈 3초 초과·안정화 → V0·D1·D3 정지 촬영/각 View 검증 → 통합 Observed → Backend 판정 → 다음 Step**입니다.

1. 로봇이 슬롯/전달판에 다음 조립 블록을 전달합니다.
2. 로봇이 V0로 복귀하고 실제 정지·관측 대기 준비를 확인합니다.
3. 보드 영역으로 사람의 손이 진입했는지 감지합니다.
4. 손이 보드 영역에 있는 동안 상태 확정과 다중 시점 촬영 이동을 보류합니다.
5. 손이 연속으로 이탈한 시간이 **3초를 초과**하고 별도 영상 안정 조건을 만족하면 조립 대기에서 관측 단계로 전환합니다.
6. V0부터 D1·D3 순서로 이동하며 각 관측점에서 실제 정지·영상 안정 확인 후 RGB-D를 촬영합니다. 각 View에서 즉시 인식·Depth/Grid 검증·이전 상태 비교를 수행하고 마지막에 시점 결과를 통합합니다.
7. Observed를 Backend에 전달합니다. Backend가 Current를 채택하고 Expected와 비교합니다.
8. Backend가 Step 완료와 새 전달판 비움 등 진행 조건을 확인하면 **D3에서 다음 Step의 Supply Board 이동으로 연결**합니다. 정상 종료마다 V0로 복귀하는 단계를 추가하지 않습니다. 실제 경로는 Controller가 검증합니다.

### 촬영·전환 조건

- 단순히 손이 없다는 이유로 정상 조립 사이클을 반복 시작하지 않습니다. 손 진입이 먼저 확인되어야 합니다.
- 일시 검출 누락을 이탈로 오판하지 않도록 연속 프레임으로 확인합니다. 임시 이탈 기준은 3초 초과이며 손 모델·영상 안정 기준의 실제 성능은 시험으로 정합니다. UNKNOWN·재진입·긴 프레임 공백은 이탈 대기를 초기화합니다.
- 손 진입·이탈은 사람 조립 구간과 관측 단계의 전환을 감지합니다. 실제 캡처 시점은 각 View의 이동 완료·정지·영상 안정 확인 뒤입니다. 손 이탈만으로 조립 완료나 다음 Step을 확정하지 않습니다.
- 재진입·장면 변화·STOP·활성 확인 요청 변경이 발생하면 해당 묶음으로 완료를 확정하지 않습니다. 재촬영 연결 정책은 D와 협의합니다.
- 이동 중 프레임은 조립 완료나 전달판 비움의 근거로 사용하지 않습니다.
- 다중 시점 로봇 이동은 Controller의 별도 안전 조건을 충족해야 합니다. 영상의 손 부재 검출은 안전 인증 기능을 대체하지 않습니다.
- 초기 빈 보드 확인·STOP 후 재개·보류 상태 재확인은 정상 손 진입 사이클과 별도 확인 경로입니다. 필요한 재확인을 막지 않도록 연결 정책을 정합니다.
- 카메라가 복귀하기 전에 사람이 손을 넣고 빼면 이벤트를 놓칠 수 있습니다. 대기 준비 상태 안내와 조립 시작 시점의 연결은 D/HMI와 확인해야 합니다.
- D435i가 V0를 떠난 동안 동일 V0 화면의 손 감지를 계속할 수 있다고 가정하지 않습니다. 대각점의 장면 유지·손 재진입 확인과 이동 안전은 View별 감시/Controller 연결로 검증해야 합니다.

### 보류·판별 불가 후 재관측

- V0·D1·D3 어느 View에서도 부족한 관측이 생길 수 있습니다. 나머지 View로 보완하고, 최종 통합으로도 필요한 판단이 불가능하면 `UNOBSERVABLE`과 사유를 반환합니다.
- B는 관측 품질과 실제 배치를 보고하고, D는 Expected와의 불일치·Current 채택·재관측 요청·다음 전달 보류를 결정합니다. 불일치가 사용자 변경 의도일 수 있으므로 무조건 재조립시키지 않습니다.
- 수정/관측 조건 개선이 필요하면 기존 check 종료·다음 전달 보류 → Controller의 안전 V0 복귀·정지 → HMI 수정 가능 안내 → 사람 수정 및 새 손 진입/연속 이탈 3초 초과·안정화 → Backend의 새 check와 최신 문맥 → V0·D1·D3 재관측 → 통합 반환 → Backend 재판정 순서입니다.
- 재관측은 현재 D1/D3에서 바로 시작하지 않고 V0부터 시작합니다. 이미 V0이면 불필요한 복귀 이동을 하지 않습니다. 예외적인 손 입력 없는 조건 개선 재확인은 별도 D 정책으로 명시하며 손 게이트를 임의 우회하지 않습니다.
- 이전 check를 재사용하거나 늦게 온 결과를 새 요청에 붙이지 않습니다. 한 번의 재관측 후 실패해도 그대로 보류하며 무제한 자동 반복하지 않습니다.
- STOP·로봇 오류·전달판 점유는 사람 재조립 문제와 구분합니다. 안전 복귀·정지 전에는 사람에게 수정 진입을 허용하지 않습니다.

### B 판단 불가 기준과 D 불일치 판정

| 구분 | 판단 기준 | 처리 |
|---|---|---|
| B 관측 불가 | 필요한 블록의 색·종류 분리 불가, 유효 Depth 부족, 층별 높이 불명확, 부분/혼합 표면, 방향·Grid 불정합, 시점 충돌, 필요한 영역 가림 | 내부 UNKNOWN·사유, 필요한 대상 판단 불가이면 UNOBSERVABLE |
| B 촬영/문맥 실패 | 장치 미수신, 보정 무효, STOP/재진입/활성 check 변경 등 묶음 무효 | 실패/보류 전달. 성공 또는 빈 정상값으로 바꾸지 않음 |
| D 목표 불일치 | 유효 관측의 종류·색·x·y·층·방향 및 실제 확인 영역을 Expected와 비교 | Current/차이 채택 정책에 따라 보류·의도 확인·수정/재관측 요청 |

색상/모델 confidence, Depth 유효 점 개수·비율, 층별 높이 허용차·분산, 방향 허용차, 프레임 안정 기준은 실측으로 정합니다. 현재 공통 geometry 설정의 여러 값이 null이므로 확정 운영 임계값이나 검증 완료로 표시하지 않습니다. 0.25칸 임시 Grid 검사만으로 나머지 기준까지 확정하지 않습니다.

## 8. 이전 블록 관측과 상태 유지

- 매 관측 사이클에서 새 블록뿐 아니라 기존 블록도 관측 대상으로 포함합니다.
- 영상 변화 영역만 잘라 관측하거나 이전 블록을 일괄 제외하지 않습니다.
- 현재 목표의 판별에 필요한 정보를 우선 확인하되, 실제로 확인된 기존 블록의 이동·제거도 보고합니다.
- 가려진 블록이나 검출 목록에서 빠진 블록을 자동 삭제하지 않습니다.
- 같은 층의 이전 footprint 전체가 확인되고 기존 배치가 없다는 증거가 있을 때 Backend가 제거·교체를 반영합니다.
- 이번 목표는 보이고 확인된 아래층만 가려진 경우 아래층 정보를 유지하며 이번 목표를 비교할 수 있습니다. 매번 모든 층이 동시에 보여야 하는 조건은 아닙니다.
- B의 추적값과 D가 채택한 Current가 다르면 추적값으로 Current를 덮어쓰지 않습니다.

## 9. OpenCV 이전·현재 영상 비교 — 적용 조건

팀장 제안을 설계에 적용합니다. 단, 효과는 아직 검증되지 않은 보조 기능입니다.

1. 이전 관측과 현재 관측 중 비교 가능한 동일 View의 안정 영상을 선택합니다.
2. 보드의 고정 기준으로 정렬합니다. 바뀐 블록을 고정 기준으로 사용하지 않습니다.
3. `absdiff` 등의 영상 차이를 계산해 변화 영역을 추출합니다.
4. 변화 위치·크기를 추가 확인 대상 및 진단 화면의 강조 영역으로 사용합니다.

### 제한 조건

- V0는 V0끼리, D1은 D1끼리 비교합니다. 서로 다른 View를 그대로 차분하지 않습니다.
- 기준 영상의 촬영 순번·View·보정·유효성을 기록합니다. 이전 실패 영상이나 완료된 상태로 채택되지 않은 영상을 확정 상태 영상으로 취급하지 않습니다.
- 손·그림자·조명·반사도 차이를 만듭니다. 변화량이 크다고 완료로 판단하지 않습니다.
- 보드 평면 정렬만으로 높은 블록의 시차가 제거되지 않을 수 있으므로 실제 촬영 시험으로 확인합니다.
- 정렬 실패·기준 영상 부재·비교 불가이면 보조 결과를 사용하지 않고 기존 인식 경로를 유지합니다. 차이가 없다는 이유로 필요한 조립 관측을 생략하지 않습니다.
- 변화 영역 밖의 기존 블록도 관측 대상입니다.
- 영상 차분으로 손 감지를 자동 대체하지 않습니다. 두 기능의 목적과 검증을 분리합니다.

공식 참고: [OpenCV 영상 정렬·추적](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html), [OpenCV absdiff](https://docs.opencv.org/4.x/d2/de8/group__core__array.html).

## 10. Backend로 보낼 데이터와 전송 시점

### 공통 Observed 형식

| 필드 | 의미 |
|---|---|
| `check_id` | Backend가 발급한 활성 확인 요청 |
| `observation_seq` | 촬영 순서. 다중 View 묶음은 시작 시 고정하는 방향이며 증가 범위는 협의 |
| `status` | `OK` 또는 `UNOBSERVABLE` |
| `visible_blocks` | 이번 관측 묶음에서 실제 확인한 블록 배치 |
| `verified_regions` | 특정 층의 점유 상태를 실제 확인한 영역 |
| `reason` | 판별 불가 등의 사유 |

블록 배치는 `brick_type`, `color`, `x`, `y`, `layer`, `orientation_deg` 여섯 필드입니다. `verified_regions`는 `x`, `y`, `width`, `height`, `layer`이며 단순 카메라 시야/ROI가 아닙니다.

```json
{
  "check_id": "example-check",
  "observation_seq": 1,
  "status": "OK",
  "visible_blocks": [
    {"brick_type": "2x3x1", "color": "blue", "x": 3, "y": 5, "layer": 2, "orientation_deg": 90}
  ],
  "verified_regions": [{"x": 3, "y": 5, "width": 3, "height": 2, "layer": 2}],
  "reason": null
}
```

예시는 형식 설명용이며 실제 관측/성능 증거가 아닙니다.

### 전송·채택 원칙

- 손 이탈·안정화 후 해당 요청에 대한 관측 처리를 마친 시점에 반환합니다. 매 카메라 프레임을 Current로 채택하지 않습니다.
- Backend의 check와 목표 `after` 전달은 즉시 촬영을 강제하는 명령이 아닙니다. B가 촬영 가능 시점을 판단합니다.
- 촬영 시점에 check/순번을 고정하며, 수신 시점의 현재 Step에 뒤늦게 붙이지 않습니다.
- `OK`는 필요한 대상이 판별 가능하다는 뜻이지 목표와 일치한다는 뜻이 아닙니다.
- 목표가 다르더라도 실제 유효 관측을 보고합니다. Expected를 실제 관측처럼 채워 넣지 않습니다.
- 과거 추적만으로 유지한 가린 블록은 `visible_blocks`에 새 검출값으로 넣지 않습니다. Backend의 Current에 유지합니다.
- 빈 검출 목록만으로 빈 보드를 주장하지 않습니다. 실제 확인 영역이 있어야 합니다.
- 닫힌 check·중복·역순 결과는 현재 진행에 사용하지 않습니다.
- confidence·View 정보·차분 지표·미확인 영역은 별도 진단으로 관리하며 공통 여섯 필드에 임의 추가하지 않습니다.
- 실시간 RGB 표시와 관측 결과 전송은 별개입니다. 각 View의 정지 촬영·검증 결과는 내부 표시/진단에 사용하고, V0·D1·D3 묶음 통합이 끝난 뒤 해당 check에 대한 Observed를 반환합니다.

### Day4 B–D 연결 요청 — 팀장 로컬 제안 반영

| 요청 목적 | 의미 | after |
|---|---|---|
| PLACE | 전달판 점유/비움 관측 | null일 수 있음 |
| ASSEMBLY | 현재 Step 목표를 포함한 실제 배치 관측 | 현재 Step 목표 |
| CURRENT | 실제 조립 상태 재관측 | null일 수 있음 |

- `after=null`만으로 PLACE와 CURRENT를 구분하지 않습니다. 요청 목적을 명시적으로 받습니다. CURRENT는 확인할 실제 범위의 판단 가능성을 별도로 검증하며 ASSEMBLY의 after 필수 검사를 그대로 적용하지 않습니다.
- 촬영 시작 시 `check_id`를 고정하고 결과에도 그대로 반환합니다. 묶음 중 요청이 바뀌면 새 요청으로 다시 태깅하지 않습니다.
- D가 준비했다는 연결 방식은 `connect(bridge) → bridge.bind(handler)`와 `submit_observation` / `submit_place` / `submit_failure` callback입니다. 목적·식별자·실패 의미를 유지하되 실제 함수 signature와 봉투 형식은 D 로컬 코드와 맞춰 연결 검증해야 합니다.
- Observed 공통 필드는 유지합니다. 전달판 EMPTY/OCCUPIED/UNOBSERVABLE은 조립 Observed와 별도 결과로 반환하고 미수신·실패를 EMPTY로 처리하지 않습니다.
- 정상 조립·빈 전달판·관측 불가·늦은 결과를 연결 시험합니다. 이는 팀장 미게시 로컬 연결부를 반영한 요구사항이지 실제 생산자 연결 또는 GitHub 게시 완료 기록이 아닙니다.

## 11. 전달판 확인과 HMI

- 조립판 관측과 전달판 상태는 독립적으로 확인합니다.
- 전달판은 확인된 `EMPTY`, `OCCUPIED`, `UNOBSERVABLE`과 사유로 구분합니다. 대기/미수신을 EMPTY로 바꾸지 않습니다.
- 이전 전달 전의 EMPTY 프레임을 새 전달의 비움 근거로 재사용하지 않습니다.
- 다음 전달은 Step 검증·현재 문맥의 전달판 비움·활성 실행 없음·STOP/오류 없음 등의 D 조건을 충족해야 합니다.
- 정상 Step마다 사람이 완료/비움 버튼을 누르는 흐름을 추가하지 않습니다.
- HMI에는 관측 대기·손 진입·안정화·관측 중·판별 불가·차이 사유를 설명하는 방향입니다. 구체적인 상태명과 화면 구성은 D와 협의합니다.

### 실시간 이전/다음 상태 동시 오버레이

- 각 관측점에서 정지해 실제 투영이 유효한 동안 라이브 RGB 위에 **이전 Backend 채택 Current와 현재 Step 완료 후 Expected**를 서로 다른 색의 반투명으로 동시에 계속 표시합니다. 여기서 다음 상태는 다음 Step 목표가 아니라 현재 Step을 수행한 뒤의 Expected입니다.
- V0·D1·D3마다 실제 카메라 자세·내부 파라미터·Camera→Board 변환·실측 stud 간격/층별 높이로 3D 투영합니다. V0 그림을 다른 View에 그대로 붙이지 않습니다.
- Current/Expected·버전·요청 문맥은 관측 묶음 시작 시 고정합니다. 첫 배치 기준점은 Job 동안 고정하며, 원래 목표에 평행 이동을 한 번만 적용하고 실제 Current나 이미 이동된 Expected를 다시 옮기지 않습니다.
- 가린 과거 블록의 그림은 과거 기록 안내이며 이번 실제 검출 증거가 아닙니다. 이동·미보정·잘못된 투영·상태 미수신이면 오버레이를 숨기고 사유를 표시합니다.
- 별도 표시 스트림/진단으로 처리하고 Observed에 이미지·추가 필드를 임의 삽입하거나 필수 JSON 파일을 늘리지 않습니다. 실제 Qt/HMI 프레임 전송과 관측점 라이브 연결은 미검증·미연결 부분입니다.

### 사람 지지 요청 기능 — 검토 제안, 확정 공정과 구분

- U는 이번에 위에 놓을 블록, L은 그 아래에서 사람이 지지할 블록입니다. L–아래 블록과 U–L의 실제 배치상 결착 stud가 각각 4개 미만인 경우 L 지지를 요청하자는 팀장 제안입니다. 보드 위 1층은 보드 전체 지지로 제외합니다.
- A가 확인된 Current와 Plan으로 결착점·지지 대상을 계산하고, B는 실제 배치, C는 요청 문장·응답 해석, D는 HMI·요청 실행·진행을 담당하는 안입니다. 비전이 물리적 체결·하중 안정성을 증명하는 기능은 아닙니다.
- 여러 아래 블록의 결착점은 중복 stud를 중복 합산하지 않으며, U–L별 기준과 합산 기준의 선택은 A/D와 정의를 확정해야 합니다. 기존 최소 기하 지지점 검사와 도움 요청 기준은 다른 목적입니다.
- 지지 손이 남아 필요한 영역을 가리면 현재 관측 규칙상 확정할 수 없습니다. 준비 확인·지지 유지·해제 안내·정지/재계획 시 취소 정책은 별도 계약이 필요합니다. 안정성 확인 없이 손을 빼라고 지시하거나 기존 이탈 게이트를 자동 해제하지 않습니다.

## 12. 검증 계획과 지표

### 시험 사례

- 변화 없음, 정상 조립, 위치·색상·방향·층이 다른 배치.
- 손·그림자·조명만 변화한 장면.
- 손 진입/이탈, 일시 검출 누락, 관측 중 재진입.
- 이번 목표가 가린 장면, 확인된 아래층만 가린 장면.
- 기존 블록 이동·제거, Depth 부족·반사·시점 충돌.
- 보드 경계 배치와 footprint 초과, 전달판 점유/비움/판별 불가.

### 지표 분리

| 구분 | 측정 항목 |
|---|---|
| 보조/품질 | 변화 픽셀 비율·위치·크기, 정렬 오차, 흐림, 유효 Depth 비율 |
| 인식 성능 | 사람 정답 대비 여섯 배치 필드와 개수의 완전 일치율, 위치·각도 오차, 관측 가능 비율 |
| 관측 시작 성능 | 손 진입/이탈 누락·오검출, 불필요한 관측 시작, 이탈 후 관측 시작 지연 |
| B–D 연결 | 미완료를 완료로 판정한 비율, 실제 완료 후 확인 시간, 판단 가능한 장면의 불필요한 보류율 |

팀장 제안의 incorrect completion rate(미완료를 완료로 처리한 비율), deviation detection rate(실제 차이 검출률), unnecessary next-step execution(진행 조건 미충족인데 다음 Step을 실행한 건수/비율), recovery success rate(복구 시도 중 정상 복귀 비율)도 B–D 공동 지표로 기록합니다. 사례별 실제 정답·관측·D 판정·실행을 같은 check로 연결하고 분모를 명시하며, 합성 연결 시험과 실제 영상 성능을 구분합니다.

- 정답은 사람이 별도로 기록한 실제 배치·완료 여부입니다. Expected를 실제 정답으로 대신하지 않습니다.
- 관측 가능한 장면의 정확도와 전체 관측 가능 비율을 함께 기록합니다.
- 합성 JSON/단위 시험, 실제 RGB-D 인식 시험, Backend 연결 시험, 로봇 장치 시험을 구분합니다.
- 완료 관련 지표는 B 인식만으로 평가하지 않고 D의 비교 결과까지 포함합니다.
- OpenCV 보조 기능은 먼저 V0 한 View로 시험하고, 보조 기능 사용 전후를 같은 장면에서 비교합니다. Day4 주 인식·연결 작업을 우선합니다.
- 수행하지 않은 시험을 PASS나 성능 보장으로 표시하지 않습니다.

- 손 감지 방식과 영상 안정·Depth·정렬 품질의 실측 기준. 손 이탈 임시 조건은 3초 초과입니다.
- 제공 posx/posj의 좌표계·단위·TCP/tool·안전 경로 확인과 View별 보정. 현재 View 구성은 V0·D1·D3입니다.
- 손 진입 감시 준비 시점과 HMI 안내, V0 복귀 기반 재관측의 실제 D 연결.
- 순번 증가 범위·callback·Backend 채택 상태 피드백·별도 진단 수신 경로.
- 자유 시작점과 Design 기준 블록 대응·평행 이동 계약·범위 초과 HMI 표현.

1. Supply Board 비전 기반 블록 탐색: 종류·색상·위치·방향을 인식하고 D와 좌표 변환·집기 자세를 연결.
