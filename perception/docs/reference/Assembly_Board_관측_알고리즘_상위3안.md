# Assembly Board 관측 알고리즘 상위 3안

## 적용 조건

- 카메라: M0609에 장착한 RealSense D435i **한 대**
- 관측 자세: 중앙 상부 V0와 네 사선 자세 D1(북서), D2(북동), D3(남동), D4(남서)
- 보드: 24×24 stud, 부품: 노랑·파랑 `2×2×1` 및 `2×3×1` brick
- 목표: 실제 조립 상태의 블록 종류, 보드 Grid 위치, 방향, 층수와 불확실 영역 출력
- 아래 순위는 **대안 및 확장 방법의 우선순위**다. 세 가지를 처음부터 모두 구현한다는 의미가 아니다.

## 1위 — RGB-D 높이 변화 검출 + LEGO Grid 상태 추적

**MVP 주 알고리즘.** 보드 기준 높이맵을 만들고, 조립 전후 같은 Grid의 높이 차이를 비교한다. 변화 영역이 `2×2` 또는 `2×3` Grid 형태에 맞는지 확인한 뒤, 관측 가능한 RGB로 색상을 판정한다. 이전에 확정한 블록 상태를 유지하면서 새 변화만 반영한다.

- **선정 이유:** 한 번에 블록 하나를 조립하는 흐름, 제한된 부품 종류, 규칙적인 stud Grid에 가장 직접적으로 맞는다. 같은 색 블록을 바로 위에 쌓아도 높이가 한 brick만큼 증가했는지 검사할 수 있다.
- **반사 대응:** RGB에서 하얗게 날아간 픽셀은 색상 판정에서 제외한다. 해당 위치의 **실제 유효 Depth**가 있는지 별도로 확인한다.
- **한계:** 보드 원점·평면·stud 간격과 카메라 자세 보정이 필요하다. 깊이값이 빠지거나 1층과 2층 높이 분포가 겹치면 층수를 확정할 수 없다.
- **구현 예:** RealSense RGB/Depth 정렬 및 유효값 검사, 보드 좌표계의 높이맵, Grid footprint 비교, 전후 높이 차이, 색상 분류, `UNKNOWN` 판정.

## 2위 — 다중 시점 3D 점유 융합

**1위가 가림 때문에 실패할 때 추가하는 방법.** V0·D1~D4의 유효한 Depth를 각각 보드 좌표계로 옮겨 합친다. Point Cloud로 먼저 확인하고, 필요할 때 공간을 작은 voxel로 나눠 `점유/비어 있음/미관측`을 기록한다.

- **선정 이유:** 위에서 보이지 않는 옆면과 일부 가림 영역을 사선 자세에서 확인할 수 있다. 높이맵만으로 표현하기 어려운 3D 구조에 유리하다.
- **한계:** Hand-Eye 및 로봇 자세·보드 좌표계 보정 오차에 민감하다. 모든 자세에서 가려진 영역은 여전히 미관측이다. Voxel 자체가 겹친 블록 사이의 경계를 자동으로 찾지는 않는다.
- **도입 조건:** 1위 시험에서 사선 관측 정보가 있어야 해결되는 가림 사례가 반복될 때 적용한다. 초기 구현부터 Voxel 전체를 필수로 두지는 않는다.

## 3위 — YOLO Segmentation + Depth/Grid 검증

**블록 영역 분리가 실제 병목일 때 쓰는 보조안.** RGB 영상에서 블록 후보 mask를 검출하고, 그 영역의 유효한 Depth와 Grid 형태로 위치·층수를 검증한다.

- **선정 이유:** 배경, 그림자, 블록 간 접촉 때문에 규칙 기반 RGB 분할이 잘 안 될 때 후보 영역을 얻는 데 도움이 될 수 있다.
- **한계:** 촬영·mask 라벨링·학습이 필요하다. 반사로 날아간 영역, 완전히 가려진 아래 블록, 층수는 YOLO mask만으로 확인할 수 없다. RGB가 심하게 포화되면 YOLO도 실패할 수 있다.
- **도입 조건:** 1·2위로 블록 후보를 안정적으로 분리하지 못하고, 실제 환경의 학습 데이터를 확보할 수 있을 때 검토한다.

## 공통으로 필요한 조건과 판정 원칙

1. **좌표 보정:** 관측 자세별 D435i 위치와 Assembly Board 좌표계를 알아야 한다. 보드 기준 높이를 구하지 않은 단순 카메라 거리 차이는 층수로 해석하지 않는다.
2. **Depth 품질 확인:** 빈 보드, 1층, 2층을 실제 촬영 거리와 조명에서 반복 측정해 각 높이 분포가 구별되는지 먼저 확인한다. 필터가 메운 Depth 픽셀만으로 층수를 확정하지 않는다.
3. **가려진 블록 처리:** 같은 색·같은 footprint 블록이 정확히 포개졌다면 현재 영상에서 아래 블록의 개별 경계와 색상을 직접 확인하지 못할 수 있다. 높이와 **이전 확정 상태**로 적층을 추론하며, 기록이 없으면 보이지 않는 아래 블록의 종류를 확정하지 않는다.
4. **불확실성 처리:** 색상, footprint, 높이, 관측 자세 사이의 결과가 충돌하거나 유효 Depth가 부족하면 `UNKNOWN`으로 두고 재촬영 또는 사람 확인을 요청한다. 공급 이력은 참고 정보이지 조립 완료의 증거가 아니다.

**제안 결론:** 1위를 MVP의 주 알고리즘으로 채택한다. 사선 관측이 필요한 가림 문제는 2위로 보완하고, RGB 블록 영역 분리가 계속 실패할 때 3위를 추가한다.
