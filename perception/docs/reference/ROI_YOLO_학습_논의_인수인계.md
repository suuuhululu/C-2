# ROI 및 YOLO 학습 논의 인수인계

작성일: 2026-10-05  
목적: 다른 채팅방에서 ROI 설계 및 학습 데이터 수집 논의를 이어가기 위한 정리

## 1. 확정된 환경과 알고리즘

| 구분 | Assembly Board | Supply Board |
|---|---|---|
| 카메라 | M0609에 장착한 RealSense D435i 한 대 | Logitech C270 |
| 촬영 방식 | 로봇을 이동해 여러 자세에서 RGB-D 촬영 | 고정 카메라로 RGB 촬영 |
| 목적 | 실제 조립 상태·블록 종류·위치·방향·층수 확인 | 공급할 블록의 종류·위치·회전각 확인 |

Assembly Board의 확정 조합:

**YOLO Segmentation + D435i Depth/Grid 검증 + 다중 시점 관측 + 이전 조립 상태 추적**

- YOLO: 보이는 블록의 후보 영역(mask)과 종류 인식
- Depth/Grid: 보드 기준 높이, 층수, 위치·크기·방향 검증
- 다중 시점: 반사와 가림을 다른 각도에서 보완
- 이전 상태: 단계별 변화를 확인하고 이미 확인한 아래층 블록 정보 유지
- 불확실한 결과: `UNKNOWN`으로 유지하고 재촬영 또는 사람 확인
- Voxel 융합: 복잡한 3D 점유 구조 표현이 필요할 때 추가하는 확장 기능

Supply Board의 최종 알고리즘은 이 논의에서 확정하지 않았다. 후보는 YOLO OBB, YOLO Segmentation + OpenCV `minAreaRect`, HSV 색상 분할 + `minAreaRect`이다.

## 2. Assembly Board 관측점

아래 그림은 상부에서 본 방향이다. 실제 촬영 높이·거리·기울기는 별도로 정해야 한다.

```text
D1(북서)              D2(북동)
          \          /
              V0
          /          \
D4(남서)              D3(남동)
```

- V0: 중앙 상부
- D1~D4: 네 방향의 사선 관측
- 직접교시로 정한 자세를 반복 재생할 수 있도록 저장하는 방식 검토
- `observation`은 관찰 기록을 뜻하며, 고정된 카메라 위치를 의미하지 않는다.

## 3. ROI 설정

### Supply Board

C270과 보드 위치가 고정되어 있으므로 고정 픽셀 ROI를 사용할 수 있다. 설치 위치·해상도·영상 방향이 바뀌면 ROI를 다시 확인한다.

### Assembly Board

카메라가 이동하면 영상 속 보드 위치와 윤곽이 바뀐다. 동일한 픽셀 ROI를 모든 관측점에 적용하면 블록이 잘리거나 누락될 수 있다. 사선 관측에서는 높은 등받이가 보드 평면의 영상 윤곽 밖으로 보일 수도 있다.

| 방법 | 적용 조건 |
|---|---|
| 관측점별 ROI 저장 | V0·D1~D4의 자세가 반복되고 보드가 고정될 때 |
| 보드 좌표계 기반 ROI 투영 | 촬영 시점의 카메라 자세와 보드 좌표 변환을 알고 있을 때 |
| 전체 영상 YOLO 후 3D 작업 범위 검사 | 초기 촬영 범위를 확인하거나 ROI 잘림을 줄이고 싶을 때 |

ROI는 보드 평면뿐 아니라 **보드 위 최대 조립 높이까지 포함하는 범위**로 정한다. 자세를 매번 임의로 바꾸면 저장된 픽셀 ROI를 그대로 사용하기 어렵다.

현재 검토 방향은 초기에는 전체 영상에서 YOLO를 실행하고, 유효 Depth와 좌표 변환이 있는 검출을 보드의 3D 작업 범위로 검증하는 것이다. 촬영 자세가 안정되면 관측점별 ROI 또는 좌표 기반 ROI를 적용할 수 있다. **구체적인 ROI 구현 방식은 아직 확정하지 않았다.**

## 4. YOLO 학습 계획

사전학습 모델을 실행할 수는 있지만, 필요한 LEGO 색상·규격 클래스를 인식하도록 하려면 LEGO 데이터로 추가 학습해야 한다.

학습 클래스:

```text
yellow_2x2
yellow_2x3
blue_2x2
blue_2x3
```

학습 흐름:

```text
D435i로 관측점별·조립 단계별 RGB 사진 수집
→ 보이는 개별 블록 영역을 mask로 라벨링
→ 사전학습 Segmentation 모델 추가 학습
→ 학습에 사용하지 않은 데이터로 검증·시험
→ 실패 조건 추가 촬영 및 재학습
→ 저장된 모델로 실시간 추론
```

- 완성본만 촬영하지 않고 각 조립 단계와 잘못된 조립 상태도 포함한다.
- 가려진 영역의 mask를 임의로 그리거나, 보이지 않아 종류를 확인할 수 없는 블록에 추측 라벨을 넣지 않는다. 애매한 사례의 처리 기준은 라벨링 전에 정한다.
- 서로 붙은 같은 색 블록의 개체 경계를 구분할 수 있는지 확인하고, 라벨링 기준을 일관되게 적용한다.
- YOLO 학습에 쓰는 RGB와 별도로 Depth, 카메라 내부 파라미터, 보드 좌표 변환, 촬영 자세·시각을 함께 보관하면 높이·다중 시점 검증에 사용할 수 있다.
- 모델 실행 때마다 학습을 반복할 필요는 없다. 학습된 가중치를 불러와 추론한다.
- 층수는 YOLO mask만으로 확정하지 않고 Depth와 이전 상태를 함께 사용한다.

## 5. 초기 촬영 장수 제안

다음 숫자는 **초기 MVP 실험을 위한 시작량**이며, 필요한 최소 데이터 수나 성능 보장 기준이 아니다.

| 촬영 단위 | 시작량 |
|---|---:|
| 한 조립 단계 × 관측점 하나 | 5~10장 |
| 한 조립 단계 × 관측점 5개 | 25~50장 |
| 조립 단계가 10개인 예시 | 총 250~500장 |

동일 장면의 연속 프레임을 반복 저장하기보다 여러 조립 회차에서 조건을 바꿔 수집한다.

- 보드 내 의자 위치와 실제 허용되는 방향
- 운영 환경의 조명·반사·그림자
- 같은 색 블록의 접촉·적층·부분 가림
- 정상 상태, 블록 누락, 위치·색상 변경
- 빈 보드와 블록이 아닌 물체가 들어온 장면
- 네 클래스가 특정 관측점이나 단계에만 편중되지 않는 구성

잘 보이지 않는 클래스를 확보하기 위해 개별 블록 사진을 보완할 수 있으나, 실제 조립 중 접촉·가림 장면도 충분히 포함해야 한다.

## 6. 데이터 분리 및 성능 확인

- 학습·검증·시험 데이터는 **조립 회차 또는 촬영 세션 단위**로 나눈다. 같은 배치의 비슷한 연속 사진과 여러 관측점 사진을 무작위로 섞어 성능을 과대평가하지 않는다.
- 검증에는 클래스별 오검출·누락, 개별 블록 mask 분리, 관측점별 성능, ROI 잘림을 포함한다.
- 층수 성능은 YOLO 성능과 별도로 시험한다. 실제 D435i 촬영 거리에서 빈 보드·1층·2층·3층 높이 분포와 반사 영역의 유효 Depth를 확인한다.
- 반사로 RGB가 하얗게 보이는 곳은 색상 확인이 어려울 수 있다. Depth도 따로 유효성을 확인하며, 필터가 메운 값만으로 층수를 확정하지 않는다.
- 같은 색 블록이 포개졌을 때 아래 블록의 정보는 이전 확정 관측에 의존할 수 있다. 관측 기록이 없으면 숨은 블록의 종류를 확정하지 않는다.
- YOLO confidence와 별도로 Depth 품질, Grid 오차, 다중 시점 일치도를 관리한다. 이를 합친 점수를 검증 없이 정답 확률로 해석하지 않는다.
