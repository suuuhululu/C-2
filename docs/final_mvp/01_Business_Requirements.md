# 01. 서비스 요구사항 — 최종 통합 갱신

## 2026-10-12 최신 적용 기준

최신 기준: 2026-10-12. 원격 integration 727d101(대상 코드 기준), main afd75d0b와 로컬 미병합 수정을 구분한다. 최신 확정 책임은 C 설계/대화 승인·의도, A 계획/도움/경로·동일 B/D 공유, B Expected/전체 관측 영역 비교/실제 Current·revision, D 실행/지정 검사/진행·HMI/제스처/기존 이력·웹이다. 인터페이스 결정·버전·배포는 수현이 담당한다.

서비스 목표는 사용자와 C의 대화로 커스텀 의자를 설계·승인하고, A가 공정·도움·경로를 계산하며, D가 로봇 직접 결착 또는 필요한 사람 협업을 실행하는 것이다. 정상 Step에는 별도 사용자 승인 버튼을 두지 않는다.

승인 전 수정 중 설계도 HMI에 표시하며 실행 중 승인 설계와 구분한다. 사용자 승인은 C와의 대화에서 받는다. 승인 설계를 A가 계산할 수 없으면 실패 사유를 보여 주고 수정·재승인으로 연결한다. D가 다른 샘플이나 임의 Plan으로 대체하지 않는다.

끝은 세 단계다: 필요한 Step 작업/블록 소진 → B FINAL과 누적 확인에 근거한 D 조립 종료 → D의 기존 JSONL→DB→사용자별 웹 반영. 설계 보관·사람 엄지척·로봇 전달 성공만으로 조립 완료를 만들지 않는다.

의자 한 개 약 10분은 성능 목표다. 10분 타임아웃이나 자동 종료 조건이 아니다. 아직 수정 후 실물 소요 시간과 최종 서비스 성공은 검증되지 않았다.

소프트웨어 범위는 24×24 stud, layer 1~5, 실행 후보 1~40블록이다. 노랑/파랑 2x2x1·2x3x1, 빨강 1x2x1을 사용한다. 범위 지원이 실물 파지·결착·안전 검증을 뜻하지 않는다.
