## 2026-10-12 최신 적용 기준

최신 기준: 2026-10-12. 원격 integration 727d101(대상 코드 기준), main afd75d0b와 로컬 미병합 수정을 구분한다. 최신 확정 책임은 C 설계/대화 승인·의도, A 계획/도움/경로·동일 B/D 공유, B Expected/전체 관측 영역 비교/실제 Current·revision, D 실행/지정 검사/진행·HMI/제스처/기존 이력·웹이다. 인터페이스 결정·버전·배포는 수현이 담당한다.

WAIT_C/계산 대기 중 STOP과 실제 동작 중 STOP을 구분한다. 로컬 수정은 종료된 execution_id를 정리하고 승인 목표·B Current·진행을 보존한다. MOCK 유휴 확인 STOP_IDLE을 실제 정지 성공으로 승격하지 않는다. 닫힌 의도/준비 응답으로 재개하지 않는다.

B ERROR는 처리 실패로 HOLD, UNOBSERVABLE은 관측 근거 부족으로 보류다. 원인 해소 후 명시적 재검사는 새 check_id로 같은 Plan/Step을 검사한다. 집기·접촉·슬롯·모의 장면 효과를 반복하지 않는다. 실제 실행별 종류/색상 1→6→1 슬롯 순환은 유지한다.

동일 check_id/동일 내용은 재진행 없이 무시한다. 같은 ID/다른 내용은 원결과와 충돌 진단을 보존해 HOLD, 실행 중이면 필요한 정지를 요청한다. 다른 옛 ID는 진행을 바꾸지 않는다. B Current/revision을 D가 재계산하거나 재발급하지 않는다.

NO_FEASIBLE_ORDER와 과거 SEARCH_LIMIT는 다른 실패다. A PR #28의 상태 수 제한은 제거됐다. 낮은 층 우선·최초 완성 순서 확보 후 도움 최소화이며 30초 최적화 기준은 강제 종료가 아니다. 불가 입력은 거절하고 막힌 블록/조건의 구체적인 C 전달은 추가 확인이 필요하다.

현재 승인 직후 NO_FEASIBLE_ORDER가 발생한 로컬 사례는 남아 있다. D의 계획 실패 KEEP 반복은 수정·관련 29개 검사 통과 기록이 있으나 A의 실패 원인 상세 반환은 미완료다. 불일치 KEEP 재계획은 유지한다.

로컬 full-real ROUNDTRIP 계산은 0.05 초과~0.5mm/0.5° 이내를 경고로 기록하며 큰 계산 차이·IK 실패는 보류한다. 이는 실제 목표 도달·정지 또는 체결 오차 기준이 아니다. 명령 전 실패만 조건 확인 후 명시 재개하며 실행 결과 불명은 자동 반복하지 않는다. 수정 후 실물 검증은 남는다.
