# 06. ROS2 Node 구조도 — 최종 통합 갱신

## 2026-10-12 최신 적용 기준

최신 기준: 2026-10-12. 원격 integration 727d101(대상 코드 기준), main afd75d0b와 로컬 미병합 수정을 구분한다. 최신 확정 책임은 C 설계/대화 승인·의도, A 계획/도움/경로·동일 B/D 공유, B Expected/전체 관측 영역 비교/실제 Current·revision, D 실행/지정 검사/진행·HMI/제스처/기존 이력·웹이다. 인터페이스 결정·버전·배포는 수현이 담당한다.

기능 책임과 실제 ROS 노드 배치를 구분한다. C 설계/대화, A 계획·재평가·경로, B 관측/Expected/Current, D 실행·검사 요청·진행/HMI·제스처는 논리 경계다. 모든 Python 함수나 HMI 위젯이 별도 ROS 노드여야 한다는 요구는 없다.

A 어댑터의 동일 계획 B/D 공유 → D 지정 검사 → B 확정 결과 → D 실행/보류 연결을 기존 함수·콜백에서 우선 정렬한다. 새 Topic/Service/Action 이름·ACK·큐를 문서만으로 발명하지 않는다.

Robot 연결은 D의 실제 실행 조건·슬롯·Contact/도움 경계를 유지한다. A 경로 후보를 수신했다는 이유만으로 드라이버 명령을 내리지 않는다. 실제 RobotState·도달·정지·파지 피드백은 합성 결과와 구분한다.

STOP·재계획 시 검사 취소 확정과 Robot 정지를 별도로 확인한다. 늦은 검사 결과는 진행을 바꾸지 않으며 B 취소 경계 뒤 Current 쓰기도 차단해야 한다. MOCK STOP_IDLE은 REAL 정지 증거가 아니다.

실행용 Isaac 입력에는 API 0.5/4층의 과거 가정이 남는다. 현재 A API 0.5.1 및 5층 소프트웨어 범위에 맞춘 전체 계획→재평가→경로 요청 정렬과 실제 Isaac 물리 실행은 미완료다.
