# 07. HMI·웹앱 화면 설계 — 최종 통합 갱신

## 2026-10-12 최신 적용 기준

최신 기준: 2026-10-12. 원격 integration 727d101(대상 코드 기준), main afd75d0b와 로컬 미병합 수정을 구분한다. 최신 확정 책임은 C 설계/대화 승인·의도, A 계획/도움/경로·동일 B/D 공유, B Expected/전체 관측 영역 비교/실제 Current·revision, D 실행/지정 검사/진행·HMI/제스처/기존 이력·웹이다. 인터페이스 결정·버전·배포는 수현이 담당한다.

C와 대화 중 수정 후보를 즉시 보여 주고, 실행 중 승인 Design과 별도 영역/상태로 표시한다. 설계 승인은 C 대화에서 받는다. Step마다 사용자 승인 버튼을 추가하지 않는다. 후보 표시와 승인·Plan 채택·조립 완료를 구분한다.

화면에는 B 판정·Current revision·Expected·차이·관측 한계와 D 실행/검사/의도/변경 대기/정지 상태를 구분한다. 오류·KEEP 보류·재개 거절의 원 사유를 HMI snapshot 및 JSONL에서 보존한다. 초기 검사만 남은 로봇 실패를 재검사 가능한 Step 상태로 표시하지 않는다.

계획 실패 대화의 KEEP은 목표와 Current를 유지한 보류다. 같은 실패 질문을 자동 반복하지 않는다. REVISE에 Design이 없으면 수정 중/변경 대기를 표시하고, 후보가 오면 Preview→Review→C 대화 APPROVE 이후 A 계산한다.

로컬 full-real은 결착 전 편 손을 인계 요청으로 사용한다. 집기 전 요청 보관과 새 RECEIVE 응답을 구분하며 Contact 중 전환은 없다. 인계 중 계속 보이는 편 손을 STOP으로 재해석하지 않고 정지는 HMI로 요청한다. 승인 목표는 보존하고 실제 사람 조립 실행 방식과 원래 A 방식을 구분해 기록한다.

시작·정지·재개·홈 복귀는 실제 실행 조건을 따른다. 요청 송신과 실제 정지를 다르게 표시한다. 제스처는 도움 준비/전달/사람 작업 신호이며 Current 확정이나 안전 장치를 대신하지 않는다.

승인 Design 저장은 개인 보관 기능이다. B Current·조립 완료를 생성하지 않는다. D의 기존 JSONL→DB 흐름으로 계획·검사·의도·설계 변경·완료를 적재하고 사용자 소유권을 따라 웹 조회한다. 공개/해제는 사용자 선택이며 별도 B 저장 경로를 추가하지 않는다.
