# 최종 MVP 개발·통합 단계

갱신: 2026-10-07. [최종 MVP](10_FINAL_MVP.md)의 커스텀 의자 직접 결착·사람 지지·세 단계 종료를 기준으로 합니다. 아래는 작업 순서 제안이며 완료 날짜·진행률이 아닙니다. 기존 Day1~4 전달형 개발·시험 이력은 [STATUS](STATUS.md)와 [Day4 계약](06_CONTRACT_DRAFT.md)에 보존합니다.

| 단계 | 목표 | 필요한 제공물 | 종료 확인 |
|---|---|---|---|
| 1 | 최종 이행 계약 | 설계 확정·순서/경로·좌표·지원·Vision·사용자 소유자/웹 논리 계약 | 생산자/소비자 책임과 미확정 필드·실패 의미 확인 |
| 2 | 설계부터 실행 준비 | 커스텀 의자 대화·명시 확정, 순서/경로 결과, Backend 채택·HMI 상태 | 미확정/무효 계획은 차단, 채택한 동일 Design/Step 표시 |
| 3 | 첫 블록 직접 결착 | 공급판 파지·조립판 접근/접촉/삽입, 실행/관측 근거 | 단일 블록 실측·제어권·정지·실패 검사; 전달판 시험과 구분 |
| 4 | 고정 도움·반복 Step | LOW/HIGH 규칙·위치·요청별 준비/부정·알림·지지 유지 가정 | HIGH 미준비 차단, 응답 오류·관측 불가·실패 분기 검증 |
| 5 | 세 단계 종료·웹 이력 | 블록 사용 기록·최종 Vision/Backend 판정·사용자별 DB/웹 조회 | 마지막 블록만으로 종료 금지, 두 사용자 분리·저장/반영 실패 확인 |
| 6 | 전체 장치 수용 검사 | 확정 Design→직접 결착→지원→최종 판정→DB/웹 증거 | 모의/실제 DB·웹/Camera·Robot 결과와 실패·한계 별도 보고 |

기존 C/A/B/D 분담은 [팀 가이드](02_TEAM_GUIDE.md)를 따릅니다. Motion Planning·웹 담당 재배정과 세부 구현은 합의 대상입니다. 담당 확정 없이 다른 팀원의 모듈을 대신 구현하지 않습니다.

## 시험 시나리오

| 시나리오 | 기대 결과 | 준비할 증거 |
|---|---|---|
| 설계 대화·확정 | 요구 구체화와 사용자 확정 뒤에만 순서/경로 생성·채택 | 대화·확정된 Design 버전·계획/경로·HMI 표시 |
| 첫 Step 자동 시작 | 실행 전제가 유효하면 공급판→조립판 직접 결착 | 집기·접근·삽입·실제 결착과 Step 확인 |
| HIGH 지지 | 요청 위치 안내·유효 긍정·알림 후 실행 | 요청/응답 식별과 시각·지지 유지 가정·지원 종료 |
| 부정·불명확·옛 응답 | 실행하지 않고 현재 요청 대기/설명 | 제스처/HMI 입력과 거절 근거 |
| 접촉/관측 불확실 | 완료 선언 보류·재관측/사람 확인·원본 증거 보존 | F/T·Vision·Human 증거와 판정 이유 |
| 마지막 블록 사용 | 1단계만 종료, 최종 Vision/Backend 판정 전 조립 완료 금지 | 남은 계획·최종 요청/관측·판정 로그 |
| 사용자별 저장·웹 반영 | 해당 사용자의 Design/조립 기록만 조회 | 두 사용자–Job 연결·DB 기록·웹 화면/조회·권한 실패 |
| DB/웹 실패 | 미저장/미반영 사유 표시, Robot 재실행 없음 | 물리 완료와 저장/반영 상태·오류 기록 |
| STOP·지연·중복 | 안전 정지 우회·중복 결착 없음 | 실측 정지·재개 전제, 활성/닫힌 요청 Fixture |

첨부 접촉·복구 연구의 E1~E7은 [연구 설계](suhyun_individual_research_topic.md#16-검증-실험-계획)의 별도 실험 계획입니다. 이번 문서 PR은 시험 수행·실험 성능 달성을 뜻하지 않습니다.

## 매일 공유와 변경 관리

완료 기능·검사 대상/결과·실패 입력·미검증·다음 연결을 공유합니다. 개발 과정에서 최종 목표가 바뀌면 날짜·이유·영향 계약을 직접 관련 문서에 기록합니다. 기존 원자료·시험값을 새 목표에 맞춰 다시 작성하지 않습니다. Isaac Sim·2PC·지속 손 감지·자동 재파지/제거는 새 필수 범위로 추가하지 않습니다.
