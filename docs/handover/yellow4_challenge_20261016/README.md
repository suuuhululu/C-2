## 다른 컴퓨터에서 가져오기

기존 checkout에 미완료 변경이 있으면 보존하고 별도 clone을 사용한다. 아래는 새 폴더를 만드는 예시이며 이미 있는 폴더를 덮어쓰지 않는다.

```bash
git clone --branch codex/integration-challenge --single-branch \
  https://github.com/suuuhululu/C-2.git c2_integration_challenge
cd c2_integration_challenge
git status --short
git log -3 --oneline
```

Git만으로 이 폴더의 선별 원시 JSON/JSONL·진단 소스·프롬프트를 받을 수 있다. 과거 `logs/`, 사진/영상은 Git에 없으며 아래 별도 보관본이 필요하다. 원시 기록의 `/home/rokey/...`는 출처 경로로 보존한 것이고 새 PC에서 실행할 경로가 아니다. `manifest.json`이 원래 경로와 휴대용 사본을 연결한다. 원래 로그 경로가 없다는 이유로 이미 확보한 사실을 다시 측정시키지 않는다.

원본 PC의 별도 보관본은 `yellow4-challenge-local-evidence-20261016.tar.gz`다. 다른 PC로 복사한 뒤 빈 디렉터리에 풀어 사진/영상과 원로그를 먼저 검토한다. 기존 로그 위에 덮어쓰지 않는다. tar 내부 manifest의 SHA256으로 복사 여부를 확인한다.

## 목표와 접근

노랑2x2x1 한 블록을 공급1번에서 잡아 조립판(17,17)1층의 stud에 먼저 걸고, 회전하며 나머지 stud를 진입시키는 결착을 검증한다. 이후 독립 재파지/분리축으로 부분·전체 해제하고 회수한다. 다른 팀원 checkout, Round2 기본 step/Plan/B Current는 변경하지 않는다.

체결은 끼워맞춤, 회전은 동작 전략이다. RG2는 파지 유지, 회전은 로봇 관절이 수행한다. J4 단독 회전과 실제 접촉축 회전은 다르다. 기존 edge_first_seating 기하로 명시 축 주위의 TCP XYZ 원호와 SO(3) 자세를 함께 계산한다. 의도적 접촉 중 수평·XY·HJK 보정으로 축을 밀지 않는다. 분리는 결착축 복사나 역재생을 사용하지 않는다.

연구 원문은 단계 설계 문서의 세 링크를 따른다. CMU 전용 도구의 attaching/twisting이나 힘·비전 센서 결과를 RG2/M0609/D435i에 그대로 적용하지 않는다.

가상축은 TCP 아래40mm·격자X 방향의 실험용 축이다. 실측 축이 아니다. TCP는 제어기 FK 기반이며 독립 계측 정확도가 아니다. 위 결과를 stage3의 등록된 블록 상공 원호 완료로 승격하지 않는다. 실제 블록 회전 결착/분리/회수는 미검증이고 stage2~7 상태는 PREPARED_FOR_FIELD_TEST다.

원호 후보5deg, 접촉 후보6mm/s·1deg/s·45N·모멘트 변화1Nm도 실물 검증 조건이 아니다. raw합력45N은 하강 중단값이고 일정 힘 제어나 체결/해제 판정값이 아니다. 윗면 누름은 회전 결착·개방 후 유지 확인 뒤 별도 실측 패드 정보로 준비한다.

## 경로 및 임시 스크립트의 한계

공급 관측높이374mm를 조립판까지 유지한 첫 후보는 비정상 IK와53.4mm FK오차로 거절됐다. 몸체 우회점에서 기존194.73mm 높이로 낮춘 후보는 endpoint 해가 나왔으나, 홈→공급 직선 구간의 J1/J6 민감도가 컸다. 홈→몸체 우회점→공급으로 수정한 후보의152샘플에서 비정상 해와10deg 초과 인접 변화는 없었다. 이것은 연속 경로 충돌 검증이 아니다. 현장에서는 사용자가 수동 이동하면서 높이/자세가 달라졌으므로 계산 후보 전체가 실제 실행됐다고 기록하지 않는다.

`diagnostic_sources/*.py.txt`는 당시 시험 소스를 보존한 텍스트다. 실행 파일로 제공하는 것이 아니며 자동 재개/재전송에 사용하지 않는다. 출발 관절·폭이 하드코딩돼 있고 당시 보조 동작만을 위한 것으로, 본시험 launcher의 대체물이 아니다. 실패 원인 중 null 통신timeout과 NumPy float32 변환 누락은 당시 파일에서 수정됐다.

## 현재 상태와 다음 작업

10월14일 마지막 조회 영상은 공급판이고 조립판 RGB-D가 아니었다. 10월15일 후속 기록은 **다른 시험이 장비 사용 중, 로봇/카메라/서비스 접속과 배치 변경 없이 오프라인 준비만**이다. 10월16일 인계 시 현재 로봇/블록 위치·파지는 UNKNOWN이다. 과거 resume.json을 현재 상태나 MoveJ 복구 목표로 사용하지 않는다.

실제 본시험을 막는 것은 FIELD_CONTACT_GEOMETRY_REGISTRATION이다.

1. 같은 파지의 실제 블록 pose를 BASE 또는 명시된 프레임에 등록해야 TCP–블록 변환을 산출할 수 있다. 교시 TCP 두 개와 약5mm 높이만으로 전체 변환이 측정됐다고 하지 않는다.
2. 실제 밑면–stud 접촉선 위치와 회전 부호/초기각이 필요하다. Y감소 측/X방향 정보는 방향 선택이고 3D축 측정이 아니다. stud행 중심, 외곽선, inferred4.4mm를 확정 접촉축으로 쓰지 않는다.
3. 기존 보정은 PROVISIONAL_NOT_FOR_MOTION이다. 올바른 조립판 RGB-D/같은 정지 TCP/검증된 카메라–BASE 변환과 가림·불확실도 검토, 또는 등록된 지그/측정 도구가 필요하다. 사진 두 장이나 cropped RGB만으로6Dpose를 확정하지 않는다.

다음 담당자는 **먼저 저장 자료와 사용 가능한 계측 방법을 검토해 구체적인 측정 계획을 제시**한다. 장비 사용이 끝나고 실행 준비가 된 뒤에만 필요한 현장 한 단계를 요청한다. profile을 준비하기 전에 공급 복귀→재파지→착좌를 반복시키지 않는다. 수동교시는 대략 위치/여유로 안내하고 소수점 강제를 하지 않는다. 필요 실제값은 capture에서 읽는다. JSON/행렬은 담당자가 작성한다.

장비 사용 가능 확인 후의 순서는 실측관계/축 등록→등록된 파지의 무접촉 상공 원호→최초 걸림/부분 회전→완전 결착/개방 후 유지→독립 재파지/분리축→부분/전체 해제→수직 이탈/회수/빈 목표→단일cycle→반복이다. 자동 장치 시험이 가능하다고 포장하지 않는다. STOP/응답 불명 뒤 개방·복귀·명령 재전송·재시도·회수 금지다.
