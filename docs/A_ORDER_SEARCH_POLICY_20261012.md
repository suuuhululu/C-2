# A 완성 순서 탐색·사람 도움 정책 — 2026-10-12 변경

## 변경 이유와 동작

큰 Remaining에서 최초 완성 순서를 찾기 전에 사용하지 않는 다음 후보까지 평가하던 비용을 줄인다. 완성 가능한 순서를 먼저 확보하고, 그 뒤 도움 단계·직접 조립 단계·도움 동작 수를 사전식 순서로 최소화한다. 최초 탐색은 지연 DFS와 배치 subset 중복 제거를 사용한다. 단계 종료 후 도구·손을 철수하는 기존 모델이므로 같은 배치 subset의 이후 가능성은 이전 방법 선택에 따라 달라지지 않는다는 전제를 유지한다.

아래 블록과 XY 영역이 겹치는 위층 블록은 아래 블록보다 먼저 배치할 수 없다. ROBOT_GRIP만 허용하는 STUD_RULES에서는 모든 활성 파지 축이 막히는 필요한 순서 간선을 추가하고, Current의 접근 막힘 또는 간선 cycle이면 NO_FEASIBLE_ORDER를 구체 사유와 함께 반환한다. 다른 파지 축 또는 사람 직접 조립이 가능한 경우를 이 robot-only 증명으로 잘라내지 않는다. 소규모 모든 순서 열거와 결과를 대조하는 회귀 시험을 포함한다.

`whole_request()`가 새 기본 context를 구성할 때 `finish_layers=true`로 낮은 층을 모두 완료한 뒤 다음 층으로 진행한다. 명시적으로 전달한 예전 `finish_layers=false`는 비교·재현용으로 수용하며 임의 덮어쓰지 않는다. 기존 `plan_from_current()`와 원본 승인 Design, 유효 Current 배치를 보존한다. 자동 제거·설계 수정 계획이나 모드별 별도 Planner는 추가하지 않는다.

사용자의 명시적 선택에 따라 사람 손의 접근 공간·도달 거리·손과 도구/블록/장애물/다른 손의 공간 간섭 검사는 제외한다. HOLD·PRESS·MANUAL_PLACE의 위치는 도움 설명을 위한 명목 접촉 제안이며 `HUMAN_ACCESS_NOT_CHECKED`로 표시한다. 실제 손 접근 가능성을 검증한 것으로 읽으면 안 된다. 목표 블록의 지지·겹침·삽입 조건, 최대 두 손 자원, 로봇 그리퍼 접근 및 목표 블록과 정적 장애물의 충돌 검사는 유지한다.

## 연결 계약

- 현재 draft API 버전은 0.5.1을 유지한다. `HumanAction.access_assessment`는 기존 GEOMETRIC_CANDIDATE_NOT_RUNTIME_VERIFIED와 새 HUMAN_ACCESS_NOT_CHECKED를 수용한다.
- `policy.finish_layers`는 context에 맞는 boolean이고 새 기본 입력은 true다. `hand_clearance_pitch_per_side`는 새 입력에서 null이며 역사적 입력의 1도 수용한다. 원본 v4 리뷰 Schema와 보존 입력은 변경하지 않는다.
- **후속 사용자 요청으로 상태 수 제한을 제거했다.** 새 기본 context에는 max_states가 없으며, 역사적 입력의 양의 정수/null 값은 수용하되 계산 중단에 사용하지 않는다. A의 현재 탐색은 상태 수 때문에 SEARCH_LIMIT를 반환하지 않는다. 원본 보존 입력과 v4는 수정하지 않는다.
- 탐색 시작부터 30초를 추가 도움 최적화의 소프트 기준으로 사용한다. 그 전에 전역 최적성을 증명하면 바로 반환하고, 30초까지 최적성을 증명하지 못했지만 완성 계획이 있으면 그중 가장 좋은 계획을 optimal=false/HELP_OPTIMIZATION_WINDOW_ELAPSED로 반환한다. 30초에 완성 순서가 없으면 계속 탐색하여 처음 확보한 완성 순서를 반환한다. 30초 뒤 후보를 찾는 경우 추가 최적화는 하지 않는다. 상태 공간을 다 조사해 불가를 확인하면 NO_FEASIBLE_ORDER를 유지한다.
- 30초는 강제 종료/응답 시간 상한이 아니다. 초기 가능성 탐색·개별 후보 검사·완성 계획 재검사·API 변환으로 더 걸릴 수 있으며, 큰 불가 설계는 상태 수 제한 없이 오래 탐색할 수 있다. 사람 도움 없는 비용 0의 완성 계획은 전역 최적성을 즉시 증명하므로 일찍 반환한다. 부분 순서를 완성 계획으로 넘기거나 지지·두 손·로봇 접근 검사를 생략하지 않는다. 구형 MIN_HELP_COMPLETE_DESIGN_SEARCH도 완성 계획 없이 시간 때문에 종료하지 않는다.
- 완성 후보는 `calculation_status=COMPLETED`와 `planning_result.status=READY`를 함께 검사한다. 지지/중첩 오류 등에는 계산 완료이지만 planning_result가 INVALID일 수 있다.
- 모든 A 반환의 execution_allowed=false를 유지한다. B 확정 Current/revision을 D가 중계하는 계약·재평가·경로 요청 경계는 유지한다.
- D의 실물 CAD 흐름은 현재 ROBOT_GRIP/NONE 조건이다. A에서 사람 직접 조립 계획을 생성해도 해당 실물 흐름의 자동 실행 완료를 뜻하지 않는다. 실제 사람 전달 tray 프로필 및 작업 방식 분기 연결은 후속 작업이다. Isaac 0.5 입력 정렬도 별도 후속 범위다.

## 재현

기존 저장 의자 하나를 현재 A로 시험한다. --input을 생략하면 다양한 기본 집합 전체를 시험하며 --input을 반복하면 여러 새 C 설계 파일을 시험한다. 입력은 Design JSON 또는 {design,current,assembly_context} 봉투다. Current 생략은 시험용 빈 상태이며 실제 관측을 추정하는 기능이 아니다.

```bash
python3 -B planning_trial/check_diverse_designs.py \
  --source . --output logs/a-diverse-designs \
  --input planning_trial/sample_design.json
```

각 results JSON은 원본 입력·실제 context·API 전체 반환·raw_result·optimization·errors를 포함한다. 단계 누락/중복·최종 Design 일치·낮은 층 우선·선행 조건·정수 격자 지지/겹침·두 손·재평가를 확인하며 실패하면 종료 1, 모두 예상대로면 종료 0이다. ROS·RobotProcess·카메라·HMI·음향·외부 LLM API를 시작하지 않는다. 시험용 Current와 계산 성공은 실물 체결·실제 로봇 경로·사람 접근 안전·B의 실제 확정 상태를 입증하지 않는다.
