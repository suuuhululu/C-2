# 팀원 시작 가이드

## 15분 적응 연습

현재 활성화된 자동화를 사용해 연습용 Issue 하나를 만듭니다. 프로젝트는 common, 분야는 general, 작업 종류는 docs를 선택하고 목표를 “환경 확인과 Issue 사용 연습”으로 정합니다. 마감은 연습 날짜에 맞춥니다. 자동 배정을 확인하려면 담당자를 미리 지정하지 않습니다.

1. 봇 댓글과 담당자를 확인합니다. 연습자가 담당자가 아니면 팀장이 Assignees를 조정합니다.
2. 댓글에 `/team start`를 입력하고 `status:doing`으로 바뀌는지 봅니다.
3. 실제로 확인한 환경과 남은 문제를 기록합니다.
4. `/team request-date YYYY-MM-DD 연습을 위한 일정 변경`을 실제 날짜로 바꾸어 입력합니다.
5. 팀장 승인 전에는 날짜가 유지되는지, 승인 후에는 바뀌는지 봅니다.
6. `/team review`를 입력하고 동료에게 결과 확인을 요청합니다.
7. 완료 조건을 확인한 후 사람이 Issue를 닫습니다. 실기 확인을 하지 않았다면 했다고 쓰지 않습니다.

연습에서 봇이 반응하지 않으면 같은 댓글을 반복하지 말고 팀장에게 Issue 링크와 실패한 단계를 알려주세요.

## 매일 할 일

| 시점 | 팀원이 남길 내용 |
| --- | --- |
| 작업 전 | 내 Issue·확정 마감·완료 조건 확인, 시작 명령 |
| 30분가량 막혔을 때 | 관찰한 증상·시도·로그·필요한 도움, 막힘 명령 |
| 마감이 어려울 것으로 예상될 때 | 남은 일·새 날짜·변경 이유를 적어 변경 요청 |
| 검토 준비가 됐을 때 | 실행한 검사·미검증 범위·PR 또는 결과 문서 링크, 검토 명령 |
| 하루 종료 전 | 오늘 한 일 / 막힌 점 / 다음 행동 |

봇에 필요한 명령은 다음과 같습니다. 코드 블록 없이 새 댓글로 사용합니다. `/team start`, `/team review`, `/team todo`는 각각 명령만 보내세요. 결과 설명이나 PR 링크는 별도 댓글로 남겨야 합니다.

```text
/team start
/team review
/team todo
/team block 막힌 이유와 필요한 도움
/team request-date YYYY-MM-DD 변경 이유
```

진행 중 작업은 1개부터 시작합니다. `review`는 검토를 기다리는 상태이며 PR이 자동으로 생성되거나 리뷰어에게 요청되는 것은 아닙니다. PR에서 검토자를 직접 지정합니다.

## 팀에서 지킬 약속

- “완료했습니다”와 함께 다른 사람이 확인할 결과·링크를 남깁니다.
- 코드가 병합됐어도 실제 장비 검증을 하지 않았다면 실기 Issue를 닫지 않습니다.
- 마감일은 본문을 고쳐서 변경하지 않고 댓글 요청과 팀장 승인을 거칩니다.
- 담당 업무가 어렵거나 시간이 부족하면 일찍 알립니다. 자동 배정은 작업량을 합의한 결과가 아닙니다.
- 다른 사람의 작업 브랜치를 덮어쓰지 않고 작은 PR로 검토받습니다.
- AI의 코드·설명·날짜 제안을 이해하고 확인한 뒤 사용합니다. 미실행 결과를 AI에게 작성시키지 않습니다.
- 봇 운영 현황 댓글을 수정·삭제하지 않습니다. 오류는 팀장에게 Issue 링크와 함께 전달합니다.

자세한 흐름은 [Git·PR 가이드](GIT_GUIDE.md), 명령·날짜 규칙은 [Issue 자동화](ISSUE_AUTOMATION.md)에 있습니다.
