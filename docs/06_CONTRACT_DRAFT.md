# 공통 입출력 계약 초안

상태: **담당자 확인용 제안이며 확정 Schema·API·ROS msg가 아닙니다.** 개념·Owner는 최신 결정, 필드·enum·식별·정책 상세는 아래 초안입니다. 동의한 항목만 00_CURRENT_DECISIONS와 구현 계약에 반영합니다.

## 확정된 의미

- 시율 Initial / Revised는 동일 Design 형식, 세은은 Design + Current + 제약으로 사람 조립 Plan / invalid 반환.
- 홍동 Observed, 수현 Backend Current 채택·Expected 관리·비교.
- Robot에는 필요한 종류·색상 goal, 진행 feedback, 전달 성공 / 실패·사유 result.
- 함수·Mock·Real·API / ROS 변환은 같은 데이터 의미를 유지하며 transport 필드는 adapter에서 붙입니다.
- Job은 Backend가 통합에서 연결. 각 모듈 계산은 Job 없는 Fixture로 실행합니다.

## 공통 객체의 최소 내용 제안

| 객체 | 확정된 의미 / Owner | 확인할 필드·표현 |
|---|---|---|
| Brick | 블록 종류·색상·위치·층·방향 | Design 내 ID와 공급 slot 구분, 기하·anchor·rotation·layer·필수 여부 |
| Design | 목표 배치·Initial / Revised·시율 | 식별 / 버전·부모 버전·출처·블록·지원 제약 |
| Observed | 촬영 당시 실제 관측·홍동 | 관측 ID / 순번·촬영 시각·보정·가림 / 실패 / 완전 관측·항목별 confidence |
| Current | 유효 관측 채택·Backend | 채택 관측·상태 revision·블록 상태·유효성 |
| Plan | 기준 Design / Current·세은 | Plan 버전·기준 상태 revision·Step 목록·검증 / 사유 |
| Step | 사람 조립 작업·세은 | 블록 목표·동작·선행조건·효과·Robot 전달 필요 여부 |
| Expected | 기준 상태 + 해당 Plan 효과·Backend | 기준 Design / Plan·비교 Step·목표 배치 |
| Difference | 일치 / 차이 / 판단 불가·Backend | 대상·항목·기대 / 실제·품질·근거 |
| HRI | 유지 / 수정 / 불명확·시율 | 질문·응답 연결·기준 Design / Current·결과 Design / 재질문 |
| Delivery | 종류·색상 요청·Robot | 실행 식별·수락 / 진행 / 최종 결과·슬롯·실패·취소 완료 |

위 표의 필드명·영문 enum·시각 형식·JSON 직렬화는 아직 확정하지 않았습니다. 단순 Job 식별만으로 동일 작업의 지연 결과를 구분하기 어렵기 때문에 아래 연결을 제안합니다.

## 식별·최신성 제안

Backend의 통합 envelope에 Job·Design / Plan 버전·Step·전달 실행 ID·질문 ID·관측 ID / 순번·촬영 시각·기준 상태 revision을 연결합니다. Producer core에는 필요한 계산 데이터만 전달합니다. 실제 필수 필드와 발급 책임은 사용하는 담당자와 합의합니다.

- 이전 Plan 전달 결과는 현재 Step 완료로 반영하지 않되 이력과 실제 전달 여부 확인에 사용합니다.
- 이전 질문의 늦은 응답은 현재 질문에 연결하지 않습니다.
- 촬영 시각·순번과 해당 조립 단계 / 상태 기준으로 오래된 관측을 걸러냅니다.
- 수락과 최종 결과를 구분하며 같은 요청 재전송·timeout 후 새 요청으로 중복 실행하지 않습니다.
- 단순 동일 상태의 촬영 갱신과 블록 배치 변경을 구분합니다.

이는 G02·G04를 구현하기 위한 제안입니다. UTC ISO 8601, ID 명명법, timeout 값은 팀 확인 전 확정하지 않습니다.

## 정상 대기와 차이 판정 제안

현재 Step까지 반영한 Expected에는 아직 사람이 놓지 않은 블록이 포함됩니다. 그 누락만으로 즉시 Intervention에 들어가면 정상 조립 중에도 질문이 발생할 수 있습니다.

| 상황 | 제안 처리 | 확인 담당 |
|---|---|---|
| 손 / 로봇 가림·부분 관측 | 판단 불가·Current 유지·완료 보류 | 홍동·수현 |
| 현재 블록을 아직 놓지 않음 | 조립 대기 유지, 기존 완료 배치 변경은 별도 비교 | 홍동·세은·수현 |
| 신뢰 가능한 안정 배치가 현재 목표와 일치 | Step 한 번 완료·다음 전달 | 홍동·수현 |
| 안정 배치가 잘못된 위치 / 색 / 방향 또는 기존 배치 변경 | 실제 차이·의도 확인 | 홍동·시율·수현 |

안정 조건·손 제거 신호·프레임 수·시간·confidence 임계값·4층 가림 정책은 실제 시험 후 정합니다. 이미 낸 이전 관측으로 다음 Step까지 중복 진행하지 않도록 상태 / 관측 연결을 확인합니다.

## 오류·진행 중 변경 제안

- Plan 실패는 검증 대상·위치·사유를 Backend로 반환하고 Design 수정 / 재질문 동안 전달 보류.
- LLM / STT 호출 실패와 사용자의 불명확한 응답을 구분. malformed / unsupported 출력은 실행 Design으로 채택하지 않는 방향을 확인.
- 대화 중 Current가 바뀌면 질문 context와 최종 재계획의 기준 상태를 확인하고, 채택 전 최신 상태를 대조.
- Robot 오류·부분 완료 뒤 재개 시 실제 전달 여부·슬롯 소모·남은 동작을 사람이 확인하는 기록 / UI 결정.
- 공급 보충 신호·확인 주체와 pick 성공 / 실패별 슬롯 증가 조건 결정.

## 계약 확인 순서

1. 시율·세은: 동일 Design의 정상 / 미지원 예시.
2. 홍동·세은·수현: 동일 grid·기하·상태와 가림 / 실패 예시.
3. 세은·수현: Plan / Step 목표·효과·제거 / 재배치·전달 필요 여부.
4. 홍동·수현: callback / Topic 관계·관측 최신성·정상 대기 / 차이.
5. 시율·수현: 질문·음성·출력 오류·ID / 버전.
6. 수현: 실제 Robot driver·Action·중복 / 취소 / STOP·HMI API·로그 형식.

각 계약은 정상·invalid·경계·지연 / 실패 Fixture와 Consumer 확인 후 Schema·구현으로 반영합니다. 현재 코드나 숫자 좌표 예시를 실행 가능한 계약처럼 추가하지 않습니다.
