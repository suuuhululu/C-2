# 현재 결정과 적용 범위

> 2026-10-11 1차 통합: 사용자 요청에 따라 공통 Schema·A/D 수신·HMI·관측 영역의 1~5층 정합을 검토합니다. 기준과 남은 작업은 [인터페이스 점검](11_ROUND1_INTERFACE_AUDIT.md)을 따릅니다. B는 관측 생산, D는 Current 채택·revision 발급·완료 판정이라는 현행 책임을 유지하며, 별도 작업 브랜치의 다른 표현을 채택 결정으로 간주하지 않습니다.

갱신: 2026-10-07. 사용자의 최종 MVP 요청을 반영합니다. **개발 과정에서 수정 가능한 제품 목표**와 기존 구현·시험 상태를 구분합니다. 제품 흐름은 [최종 MVP](10_FINAL_MVP.md)를 우선하고, 과거 Day4 계약은 [06_CONTRACT_DRAFT.md](06_CONTRACT_DRAFT.md)에 보존합니다. 첨부 연구 문서의 지시·초안은 사용자 요청 자체와 구분합니다.

## 최종 MVP 목표

1. 서비스 시작 시 LLM과 사용자 대화로 커스텀 의자를 디자인하고 설계를 확정합니다.
2. 확정 Design으로 조립 순서·경로를 생성해 Backend로 넘기고 HMI에 반영합니다.
3. 실행 전제가 갖춰지면 첫 Step을 바로 시작합니다. 로봇이 supply board에서 집어 assembly board에 결착합니다.
4. 디자인상 지지가 필요한 부분은 사람에게 고정 도움을 요청합니다. [연구 설계](suhyun_individual_research_topic.md)의 LOW/HIGH·지원 위치·엄지척/엄지+검지·요청별 준비·지지 유지 가정을 반영합니다.
5. 조립 종료는 필요한 블록 모두 사용 → Vision 완성상태 확인과 Backend 최종 판정·종료 → 사용자별 현재 설계/조립 기록 DB 저장과 웹앱 반영으로 구분합니다.

## 유지하는 상태·실행 원칙

- Current/Expected와 최종 조립 상태는 Backend/State Manager가 관리합니다. Vision은 관측·검증 증거, Controller는 실행/접촉 결과, HMI는 표시·응답을 제공합니다.
- 실행 완료·파지 해제·블록 사용 종료를 조립 완료로 처리하지 않습니다. 최종 Vision 근거와 채택 Design·누적 확인 기록을 Backend가 대조합니다.
- 확인 완료 아래층 가림은 기록을 보존합니다. 이번 대상 관측 불가이면 Current 유지·완료/다음 실행 보류, 유효한 불일치는 실제 값과 사유를 기록합니다.
- Expected는 Plan 채택 시 고정 기준 Current와 완료/현재 Step 효과로 계산합니다. 불일치 Current로 목표 기준을 바꾸지 않습니다.
- 활성 요청·계획/상태 버전에 맞는 결과만 채택합니다. 닫힌 요청·중복·역순 관측·옛 지원 응답으로 진행하지 않습니다.
- LLM이 저수준 joint/TCP/속도/힘·로봇 궤적을 생성하지 않습니다. 기존 pose·보정·속도·힘을 직접 결착용으로 추정·재사용하지 않습니다.
- STOP·안전 정지와 일반 지원 응답은 구분합니다. DB 기록으로 Current를 자동 복원하거나 Robot을 재실행하지 않습니다.

기존 C 시율 Design/HRI, A 세은 Plan, B 홍동 Vision, D 수현 Backend/Robot/HMI/DB·통합을 이행 기준으로 유지합니다. 첨부의 Assembly Planner/Motion Planner 역할 재배정은 제안이며 이 문서에서 확정하지 않습니다. [팀 가이드](02_TEAM_GUIDE.md)에 필요한 제공물을 정리합니다.
