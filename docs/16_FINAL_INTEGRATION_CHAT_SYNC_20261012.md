## 3. 완료된 로컬 반영과 증거

### D의 다섯 문제

로컬에는 WAIT_C STOP/재개, ERROR 후 명시적 재검사, 슬롯·장면 중복 소비 방지, 같은 check_id 내용 충돌 보류, Design 없는 REVISE 변경 대기가 반영됐다. 승인 Design·B Current/revision·진행 이력을 유지하며, 동일 검사 ID의 원결과와 충돌 진단을 보존한다. 재검사는 새 check_id를 쓰지만 집기/접촉을 다시 실행하거나 슬롯을 다시 소비하지 않는다. MOCK 유휴 확인과 REAL 실제 정지 증거를 구분한다.

증거는 [D 수정 안내](final_mvp/08_Exception_and_Error_List.md)와 `logs/d-fix-20261012/verification.json`이다. 기록의 앱 단위 43 passed, 통합 78 passed, 외부 D 948 passed는 각각의 당시 집합이며 모두 실패/오류/skip 0·종료 0이다. 이번 문서 작성에서 다시 실행한 결과가 아니다. 이후 다른 D 전체 검사에서 남은 기존 실패와도 구분한다.

Design 없는 REVISE를 받을 수 있는 소비부는 준비됐지만 실제 C의 비동기 수정 후보 전달 왕복이 완료됐다고 단정하지 않는다. KEEP의 관측 차이 재계획과 계획 실패 대화의 KEEP 처리도 구분해야 한다.

### A PR #28의 계획 정책

로컬 A에 원격 PR #28을 선별 적용했다. 낮은 층을 완료한 뒤 다음 층으로 진행하는 새 기본 입력, 최초 완성 순서 확보 후 도움 최소화, 상태 수 제한 제거가 핵심이다. 현재 A는 상태 수 때문에 SEARCH_LIMIT를 반환하지 않는다. 과거 max_states/SEARCH_LIMIT 재현 기록은 당시 결과로 보존한다.

추가 도움 최적화의 30초 기준은 응답 제한/강제 종료가 아니다. 완성 계획이 없으면 탐색을 계속하고, 완성 계획이 있으면 최적성 여부와 최적화 종료 사유를 함께 반환한다. `COMPLETED`와 `planning_result.status=READY`를 함께 확인하며 불가한 입력의 NO_FEASIBLE_ORDER 의미를 유지한다.

사람 손 접근 공간·도달/간섭 검사는 사용자 결정에 따라 제외했고 도움 제안은 `HUMAN_ACCESS_NOT_CHECKED`다. 지지·겹침·최대 두 손·로봇 그리퍼 접근 검사는 유지한다. 명목 도움 후보를 실제 사람 작업 공간 검증 완료로 표현하지 않는다. 상세는 [A 정책](A_ORDER_SEARCH_POLICY_20261012.md)이다.

de59b08에서 기본/저장 의자가 실패했던 기록을 최신 A에도 그대로 적용하지 않는다. 로컬 기본 의자 계산 개선과 원격 A 업데이트를 구분하고, 모든 승인 설계가 해결됐다는 주장도 하지 않는다. 원격 PR #31은 A 단일 코드/실행 예제/원자료 보존 안내를 정리한 문서 변경이며 D나 SIM 전체 연결 완료를 뜻하지 않는다.

### 교시 캘리브레이션

6점·2점 × 0°/90°의 네 모서리 교시를 방향별 좌표 변환에 연결했다. 사용자 확인에 따라 2점의 반대로 기록된 각도 이름과 끝쪽 최소 점유 좌표를 정정하고 실제 TCP 측정값은 보존했다. HMI/DB 공통 좌표는 최소 점유 stud 기준이며 0° 긴 변 Y, 90° 긴 변 X다.

1층은 새 판 위치별 교시 기준, 2~5층은 기존 4점의 층간 실측 차이를 더한다. 새 교시에 과거 2mm/중심 0.5stud/TCP/파지 보정을 다시 더하지 않는다. 최대 교시 맞춤 잔차 약 0.56mm·자세 약 0.54°는 측정과 모델의 일치도다. 이전 중앙점과 최대 4.15mm 차이·일부 말단 자세 약 179° 차이가 있으므로 실물 정합/회전 경로는 별도 확인 대상이다.

근거: [좌표 감사](final_mvp/05_Interface_Specification.md), `logs/calibration-a28/calibration-report.json`. 같은 작업의 교시/A 검사 318 passed, 실행/HMI/분기 117 passed는 각각 실패/skip 0·종료 0이며 중복 합산하지 않는다.

### HMI·DB·웹

C→A→D 시험 HMI의 승인 설계 저장이 추가됐다. `C_DESIGN_APPROVED`는 Design 보관이며 B Current·Plan 채택·조립 완료를 만들어내지 않는다. 로컬 제작자 로그인/저장·공개·웹 확인과 실제 조립 성공을 구분한다. 공개/해제는 사용자 선택이다. 안내와 검사 범위는 [DB 이력](D_DB_HISTORY.md), [웹 안내](D_WEB_HISTORY_RUN.md)를 따른다. 이번 문서 작업에서 DB나 웹을 실행하지 않았다.

## 5. 최신 사용자 결정과 진행 중 개선

### 약 10분의 조립 속도 목표

의자 한 개 조립을 약 10분으로 단축하는 **성능 목표**다. 10분 타임아웃·자동 종료·새 제약을 만들라는 뜻이 아니다. 불필요한 우회/중복 이동/정차와 공정 소요 시간을 줄이는 작업이 진행 중이다. 목표 달성 여부는 실제 시나리오와 도움·사람 조립 대기를 포함한 측정으로 확인해야 한다. 아직 달성 결과는 없다.

### 모든 Step의 결착 전 손바닥 인계

사용자는 로봇 직접 조립 Step을 포함해 **결착을 시작하기 전까지 모든 Step에서 손바닥으로 사람 인계 전환**을 허용했다. 이동 중 손바닥을 보았다고 그냥 정지 상태에 머무는 대신, 이동 정지·파지 유지 확인 → 전달판 상공의 인계 위치 → 새 손바닥 응답 → 개방 → 사람이 조립 → 엄지척 → 해당 검사/진행으로 연결하는 변경이 진행 중이다.

이 결정을 과거 ‘RECEIVE 밖 편 손은 항상 STOP’ 규칙으로 덮어쓰지 않는다. 반대로 이동 중 즉시 그리퍼를 열거나 결착 중 인계로 바꾸는 것으로 해석하지 않는다. 결착 전 전환 경계·최신 요청 대응·인계 이후 실제 B 검사 연결은 완료 검증이 필요하다. 인계/엄지척은 물리 작업 신호이며 설계 승인 버튼을 대신하지 않는다.

### 접촉 미세 정렬·정차·빈 그리퍼 복귀

- 완전 체결 목표 Z+10mm는 접근 구간 경계다. 이전 ‘pre-contact보다 10mm 위’와 구분한다. 16mm는 기존 입력의 stud 간격이며 돌기 높이는 4.5mm다.
- 기존 D의 제한 XY·Z축 주변 좌우 회전 기능을 별도 시험 모드로 연결하는 작업이 진행 중이다. 10mm 내내 회전하거나 ‘20N 접촉 후 그 자리에서 즉시 하강’으로 확정하지 않는다. 실제 접촉 후 필요한 구간에서 미세 정렬하고 완전 체결 목표/기존 확인 절차를 기준으로 종료한다.
- 결착 전 약 30.1mm 위 중간 정차 감소와 빈 그리퍼 복귀 시 place board를 건너뛰어 BODY_BYPASS로 이동하는 변경을 준비 중이다. 사람 전달판 경로와 실제 인계/힘 제어 전환 확인은 유지한다. A 후보와 D 실행 경로를 함께 정렬해야 한다.
- 탐색 크기·힘·속도·가속도의 최종 수치나 물리 성공은 이 문서에서 새로 확정하지 않는다. 진행 중인 작업의 검사 결과와 실행 안내를 확인한 뒤 완료 상태로 갱신한다.

### ROUNDTRIP과 재개 진단

최근 대화에서 S06의 공급 이동 전 `IK_FK_ROUNDTRIP_MISMATCH`가 먼저 발생했고, 이후 재개 거절이 `STEP_BUSY_OR_INSPECTION_PENDING`으로 표시됐다고 보고됐다. 가짜 B의 완료 표시를 실물 조립 완료로 읽지 않는다.

작은 계산 차이를 경고로 남기는 정책과 실제 도달 불가/큰 오차 구분, 실제 목표 도달 확인 유지, 첫 실패와 재개 거절의 분리 표시는 수정 중이다. 실제 오차 크기·최종 허용값·회귀 결과가 아직 없으므로 모든 ROUNDTRIP 불일치가 무조건 통과한다고 문서화하지 않는다.

## 6. C PR #30과 아직 남은 연결

PR #30 검토에서는 직접 설계 변경/관측 차이 대화 분리, 계획 실패 문맥, 자연어 승인·의자 정면 설명이 추가됐다. 별도 사본 검사 1095 passed/1 failed, 종료 1이다. 한 실패는 새 직접 변경 해석기와 기존 spy 기대값의 불일치로 기록됐으며 삭제/skip으로 해결했다고 표시하지 않는다.

D에는 계획 실패 코드·재설계 필요 여부의 문맥 전달, 계획 실패 대화의 KEEP 뒤 같은 계산을 반복하지 않고 목표/Current를 유지해 보류하는 처리, Preview/Review 동안 metadata·실패 사유 유지, HMI 정면 캡션 정렬이 남는다. 관측 차이 `c.intent`의 KEEP 재계획과 구분한다. 상세는 [PR #30 검토](final_mvp/10_Measurement_and_Operation_Validation.md)다.

원격 `727d101`에서도 실행용 Isaac whole 요청의 API 0.5와 Scenario 4층 제한이 남는다. API 0.5.1의 전체 계획→재평가→경로 정렬은 미완료다. 공급판 RGB 중심 후보도 D 실제 호출/픽셀→파지 좌표/종류 매핑과 미연결이다. [SIM 안내](04_ISAAC_SIM.md)와 이전 점검의 공급판 비전 절을 참고한다. 실제 B 카메라·Current 확정과 최종 검사 연결은 계속 별도 과제다.

## 7. 검증 기록을 읽는 방법

위 통과 수치는 다른 채팅의 완료 작업에 남은 JSON/JUnit 기록을 이번에 읽어 확인한 것이다. 이 문서 작업에서 앱 검사를 재실행한 수치가 아니며, 서로 중복되는 집합·과거/현재 실행을 합산하지 않는다.

외부 D의 후속 전체 검사에는 948 passed/기존 onsite 6 failed, 종료 1 기록도 남는다. 이전 D 수정 당시 948 passed/실패 0과 대상/시점이 다르다. 전체 PASS로 통합하지 않는다. 증거는 `logs/full-feature-real/rotation-motion-verification.json`과 각 XML이다.

진행 중인 접촉/인계/속도 작업에는 최종 통과 수치가 아직 없다. 실제 사용자 현장 시험 보고, 장치 없는 모의 검사, 문서 검증을 구분한다. 이번 완료 기준은 대화·근거 기록과 문서 상태 일치, 링크·표·코드 블록·변경 범위 확인이다. 코드·설정·원자료 변경과 commit/push/게시를 수행하지 않는다.
